## Strengths
- The generator extensions are small and correct on both platforms:
  - `{w,h}` sizes become `--size-logo-mark-w/-h` and `CGSize(width: 40, height: 35)`.
  - `rgba()` colours become `Color(..., opacity:)`: `color.scrim` and `semantic.scrim` in CSS and Swift, and `shadow.soft` in the Swift tuple.
  - `Tokens.ShadowBlur` is a separate enum, so the `ShadowToken` tuple keeps its shape.
  - `web/lib/assets.ts` and `Tokens.Asset` both drop `pending` entries, so no code can reference a missing file.
  - `font.*.ios` gives the iOS registered name, and the old naming rule is the fallback.
- `pending` is handled end to end. `pnpm assets` warns on each pending entry and skips it; `/assets/sky-1.png` returns 404 and nothing references it. The tokens, assets and icon generators are idempotent: `git status` stays empty after `pnpm tokens && pnpm assets && pnpm icon`.
- `scripts/sync_assets.ts` reads only from the repo (`design/assets/` and `ios/App/Resources/Fonts/`). It fails loudly on a missing or empty file or a missing `UIAppFonts` array. Every `Contents.json` it writes is valid JSON. SVG imagesets are single-scale vectors (`preserves-vector-representation`), and icons and the logo are template images.
- Old fonts are fully removed: the Bagel Fat One and Rubik TTFs and OFL files are gone from disk; `Info.plist` `UIAppFonts` lists exactly `Inter-Variable.ttf`, the only TTF in `ios/App/Resources/Fonts/`; `layout.tsx` imports only `Inter`. `layout.tsx` keeps the CSS variable names `--nf-display` and `--nf-body`, and `globals.css` still reads them.
- `testInterIsRegistered` tests real behaviour. iOS ships no Inter, so `UIFont(name: "Inter Variable")` returns nil when either the TTF is missing from the bundle or the `UIAppFonts` entry is missing. Either removal fails the test. Removing the file also makes `pnpm assets` fail first.
- `testSkyTokens` compares generated Swift values with `tokens.json` (read from the source tree), not with literals copied by hand. Except for `Tokens.displayTilt` (literal 0), `ThemeEffects` matches tokens: stroke 0/0, scallop height 0, grain 0, and motion unchanged.
- The app icon renders correctly. `AppIcon-1024.png` is 1024×1024 with no alpha channel. It shows the ink (`#111827`) eye mark centred on accent green `#65C361`: a ring with a pupil, three lashes on top and pointed corners left and right. It is clean and legible.

  - The node table covers all 8 boards plus the pending screens, and every iOS view it names exists.

### Important

**I1. `type.caption` is 12 px; the PM ruling is 13 px.**
- Where:
  - `design/tokens.json:64` (`"caption": { "size": 12, ... }`)
  - generated `web/app/tokens.css:61` and `ios/App/Theme/Tokens.swift:68`
  - `docs/accessibility.md:81` (flag 2 says "`type.caption` (12) ... only for short labels")
  - `docs/handoffs/design.md:52` (open question restates 12)
- What is wrong: The ruling sets caption at 13 px as the accessibility floor. The branch keeps the brief's 12 and documents 12 as allowed for short labels, so the docs contradict their own "13 px is the floor" flag.
- Why it matters: T102 and T103 build components on this token. Any caption they render will be 12 px, under the floor the team committed to.
- Failure scenario: T102 builds the method card description or the status badge with `--type-caption-size`. The text renders at 12 px, and the a11y review rejects it after the re-skin.
- Fix: Set `type.caption.size` to 13 (keep line height 1.4) and run `pnpm tokens`. In `docs/accessibility.md` flag 2, state that 13 px is the floor for all text except the 11 px caps eyebrow, which is the one exception. Update the open-question line in `docs/handoffs/design.md:52` to match.

**I2. Token values are not traceable to Figma node ids value by value.**
- Where: `design/tokens.json:3` (meta points to `docs/design/screens.md` for node ids); `docs/handoffs/design.md` "T100 intake record"; `docs/design/screens.md` intake log; empty commit bodies.
- What is wrong: The brief's reviewer criterion is that every value in `tokens.json` is traceable to a board node id. The docs trace values only to the four boards read in full (`21:4229`, `45:700`, `21:4340`, `21:4509`), plus a few explicit nodes:
  - `radius.m` → `45:749`
  - `type.displayM` → `21:4541`
  - the logo → `45:712`
  - the icons → `45:752`, `45:762`, `45:773`, `45:757`, `45:720`, `I45:738;7:10`
  - `shadow.soft` → `45:746`

  No doc marks which values came from a node, which came from the brief or a ruling, and which were carried over from Direction A.
- Values I could not trace to any node:
  - `color.focus` `#1E3A24` and `color.danger`: carry-overs, kept by the brief.
  - `color.scrim`: an a11y addition, not on any board.
  - `space.xs/s/m/l/xl/xxl/section`: only `page` 24 was re-read.
  - `radius.s` 6, `radius.cardL` 30, `radius.tile` 36.
  - `border.icon` 1.8: it matches `camera.svg` and the other line icons, but `check.svg` is 1.7 and `arrow.svg` 1.65.
  - `size.iconButton` 48, `size.record` 84, `size.stepDot` 8, `size.avatar` 40, `size.minTarget` 44, `size.photoMaxHeight`.
  - `type.displayL` 40 and `type.bodyL` 16: brief values, no node named.
  - `type.caption` 12/500.
  - `type.eyebrow` weight 800: the board is Figtree ExtraBold 10.
  - every `highContrast.*` value: derived.
  - `opacity.disabled`, `motion.*`, `effects.grain.baseFrequency/octaves`, `effects.scallop.amplitude/period`: inert carry-overs.
- Why it matters: The next intake diffs against this file. Without provenance, nobody can tell which values a new board can overwrite and which are a11y or legacy decisions. That is the exact purpose of the criterion.
- Failure scenario: The user's duplicate shows `space.l` = 12 on a card. The next intake cannot tell whether 16 was read from Sky or inherited from Direction A, so it either drops a deliberate value or keeps a stale one.
- Fix: Add a "Token provenance" table to `docs/handoffs/design.md` (or `docs/design/screens.md`): `token → value → source`, where source is a node id, "brief", "PM ruling", "a11y", "derived (highContrast)" or "Direction A carry-over (no Sky board)". When the duplicate is available in the fix round, fill in the node ids for the four screenshot-only boards.

### Minor

**M1. `welcome-bg.png` is about 1.2x (574×1024) for a full-bleed background.**
- Where: `design/assets/welcome-bg.png`; `ios/App/Assets.xcassets/welcome-bg.imageset/Contents.json` labels it `@2x`.
- What is wrong: On an iPhone 17 Pro (1206×2622 px), aspect-fill scales 1024 px of height to 2622 px, a 2.6x upscale. On a 3x device with web `cover`, it is similar.
- Judgement: Acceptable as a stopgap only. The scene is soft-focus plush and clouds, so the sky survives, but the mascot, the totes and their stickers will look visibly soft. It is also 762 KB as PNG on the web, where a photo would be about 100–150 KB as JPEG or WebP.
- Fix: In the fix round, export at least 1206×2622 (3x of 402×874, or 2x of 390×844 = 780×1688 as the floor). Serve it through `next/image` or as WebP on the web.

**M2. `mascot-book.png` and `tote.png` were rendered locally, not exported from Figma.**
- Where: `docs/handoffs/design.md:43-44`.
- What is wrong: They were rendered with sharp from raw fills plus mask and crop geometry. The brief says "exported from the Figma at 2x and used as-is". The deviation is documented, and on inspection both look right: the masked mascot has its sticker halo, and the tote is cropped cleanly. But they are not verified against Figma's own render.
- Fix: Re-export both from the duplicate in the fix round, alongside the four pending assets, and diff them visually.

**M3. `pnpm assets` never removes stale outputs.**

- What is wrong: An entry that is renamed, removed or switched back to `pending` leaves its file in `web/public/assets/` and its `.imageset` in the catalog.
- Failure scenario: In the fix round, `mascot-magnifier` is dropped (the handoff says it may be). Its old copies would linger if they had ever been synced.
- Fix: Before copying, delete `web/public/assets/*` files and the `*.imageset` folders that are not in the current non-pending set. Never touch `AppIcon.appiconset`.

**M4. `testAssetsAreBundled` uses a hand-written list.**
- Where: `ios/Tests/ThemeEffectsTests.swift:51-55`.
- What is wrong: A new non-pending asset added to `tokens.json` is not checked.
- Fix: Read `tokens.json` `assets` (the file is already loaded by `tokens()`), filter out `pending`, strip extensions and assert `UIImage(named:)` for each.

**M5. `mascotBook.node` is inconsistent between tokens and the handoff.**
- Where: `design/tokens.json:88` says `45:813`; the handoff (`docs/handoffs/design.md:43`) and the report say the image is from `45:815`, masked by `45:814`.

**M6. Generic imageset names.**
- Where: `ios/App/Assets.xcassets/{image,check,arrow,camera,mic}.imageset`.
- What is wrong: The logical names are `iconImage` and so on, but the catalog names are `image`, `check` and similar. Xcode generates asset symbols such as `ImageResource.image` and `.check`. These are easy to confuse with SF Symbols, and the next collision with another asset or colour set is likely.

**M7. Two `Inter()` loaders duplicate the `@font-face` rules.**
- Where: `web/app/layout.tsx:9-10`.
- What is wrong: The served CSS has 14 `@font-face` rules for 7 files. The URLs are identical, so the browser downloads each file once; this is harmless but noisy.
- Fix: Use one loader with `--nf-body` and set `--nf-display: var(--nf-body)` in `globals.css`. Optional.

**M8. `docs/accessibility.md` contradicts itself on CTA height.**
- Where: `docs/accessibility.md:8` still says "primary actions are 60"; flag 6 (`:85`) says 56 from Sky.
- Fix: Update line 8 to `size.cta` (56) with ≥44 minimum. Flag that `common.md` says 60.

**M9. `ThemeFont` weights per role are hand-mapped and untested.**

- What is wrong: The mapping matches `type.*.weight` today, but nothing checks it, unlike `ThemeEffects`.
- Fix: Add a test that maps each `TextRole` weight to the `tokens.json` number, or let the generator emit `Tokens.TypeWeight`.

**M10. Undefined CSS variables beyond the report's list.**
- Where: `web/components/ui/Field.module.css:31`.
