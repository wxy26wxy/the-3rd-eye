**Canonical brief (user, 2026-10-28; model names corrected to what the hackathon provides):**
> Our app helps artists with disabilities turn their art into products people want to buy. Artists who draw snap a photo, and Meta's Segment Anything Model (SAM 3.1) cuts out the artwork. Artists who can't draw, like people who are blind, describe their idea out loud. Muse Spark shapes the description into an image prompt, Muse Image generates the art, and Muse Spark then reads a description of the result back to them so they can refine it. The art becomes stickers and tote bags, and each one ships with an NFC tag that plays a short video of the artist talking about their work.
>
> This solves three problems: studios can only sell one-off originals locally, artists with disabilities struggle to earn income and recognition, and buyers never get to know the person behind what they buy.

Model-name audit (done): the hackathon provides **Muse Spark 1.3** (reasoning + vision; there is no "Llama"), **Muse Image 1.0** (image generation/editing), **Muse Voice Transcribe 1.0** (speech-to-text), **SAM 3.1** (segmentation), plus Muse Spark Open / Glimmer (open weights) and Muse Code. **There is no Meta text-to-speech model**: "reads a description back" = Spark writes the description; on iOS it is shown as a text card and read by the system's VoiceOver (T081 replaced the in-app `AVSpeechSynthesizer`, user decision 2026-10-29); on the web the "Read aloud" button uses `speechSynthesis`. State this plainly in README.

**Product (longer form).** Disabled creators make art in an iOS app two ways: draw (photograph a drawing on paper or a handmade object such as a toy or a stitched piece; in-app canvas is P2) or describe an idea aloud and let Muse Image generate it. The app turns the image into products (die-cut sticker, tote bag), and an AI listing agent writes the shop copy. A public website lists products with each creator's story. A buyer purchases; part of the money goes to the creator. The creator is notified in the app and composes a thank-you (text, image, or video of the making process). The startup prints the product and attaches an NFC tag. The buyer taps the tag, sees the creator's message/media, and can reply.

**Four problems it solves (user's framing; reuse verbatim in README, site, and video opening):**
1. **Art that can't sell at scale.** Most art studios serving people with disabilities can only sell original pieces locally, and once a piece sells, it's gone. We turn one artwork into products that can be sold again and again, with no inventory.
2. **Talent without income or recognition.** People with disabilities are employed at about half the rate of people without disabilities. We give them a way to earn money and be recognized as artists.
3. **No connection between buyers and creators.** Buyers usually have no idea who made what they're buying. Our NFC story tag lets them hear directly from the artist, which makes the product more meaningful and a better gift.
4. **People who can't draw are left out.** People who are blind or have low vision have visual ideas too, but they can't put them on paper. By describing their idea out loud and letting AI generate the image, they can become creators too.

## 1b. Swappable parts (user requirement: any part can be replaced, including a complete redesign)
Rule: every cross-cutting concern sits behind one interface in one place; nothing else imports the concrete implementation. Reviewers check this on every handoff.

- **Design system → `design/tokens.json` is the single source.** Colors (semantic: `bg`, `surface`, `text`, `accent`, `danger`, plus high-contrast variants), type scale, spacing, radii, motion durations, target sizes. `scripts/gen_tokens.ts` generates `web/app/tokens.css` (CSS custom properties, light/dark/high-contrast blocks) and `ios/App/Theme/Tokens.swift` (static constants + `Color`/`Font` extensions). Components and screens use only semantic tokens, never raw values; a lint rule (stylelint `declaration-property-value-disallowed-list` for hex/px in components, SwiftLint custom rule for `Color(red:` / literal `.font(.system(size:`) enforces it. Changing the whole look = edit `tokens.json`, rerun the generator. Figma variables mirror the same names so the designer's export is a token diff, not a rewrite.
- **UI components → thin, prop-driven.** Web: `components/ui/*` primitives (Button, Card, Field, Media) wrap tokens; pages compose primitives. iOS: `Components/*` likewise; screens hold no styling constants. Layout variants (e.g., shop grid vs. list) are props on `ProductGrid`, not forks.
- **AI providers → `web/lib/ai/` interfaces.** `TranscribeProvider.transcribe(audio) → {text}`, `PromptShaper.shape(transcript) → {prompt, question?}`, `ImageProvider.generate(prompt, n) / refine(ref, instruction) → {images, ref}`, `Segmenter.segment(image, hint) → {mask, svgPath}`, `Describer.describe(image) → {alt, spoken, differences}`, `ListingAgent.run(ctx) → {listing, trace}`, `StoryWriter.draft(transcript) → {text}`. Concrete implementations in `web/lib/ai/meta/*` (Muse Voice Transcribe, Muse Spark, Muse Image, SAM 3.1) and `web/lib/ai/ollama/*` (Muse Glimmer). Wiring in one file `web/lib/ai/registry.ts` chosen by env (`AI_IMAGE=meta`, `AI_STORY=ollama|meta`, `AI_FIXTURES=1`). Swapping a model = one new file + one registry line.
- **Storage → `Storage` interface** (`putPublic`, `putPrivate`, `signedUrl`, `delete`) in `web/lib/storage/`; Vercel Blob implementation today, S3/R2 possible. DB access only through `lib/db/queries.ts` (Drizzle); schema changes via migrations.
- **Payments → `PaymentProvider`** (`createCheckout`, `confirm`) in `web/lib/payments/`; `staged` today, `stripe` behind `PAYMENTS_MODE`.
- **Products → registry** `web/lib/products/registry.ts`: each type (`sticker`, `tote`) declares `printSpec` (size, dpi, bleed, cut line?), `mockupPrompt`, `priceRange`, `fileBuilders`. Adding a mug = one new entry.
- **Notifications → `Notifier`** (`notifyCreator(orderId)`): polling today; APNs/email later.
- **Content blocks on `/t/[token]`** rendered from an ordered list (`artist_video`, `thank_you`, `thread`, `about_creator`) so the tap experience can be rearranged without code in the page.
- **Copy/i18n →** all user-facing strings in `web/messages/en.json` and `ios/App/Resources/Localizable.xcstrings`; no inline strings in components.
- **Accessibility prefs → one `AccessPrefs` object** (server + web): contrast, text size, read-aloud, simple mode. On iOS after T081 only `simpleMode` is read; contrast and text size follow the system (Increase Contrast, Dynamic Type) and there is no in-app TTS.

## 1c. Traceability and rewind (user requirement: everything traceable, anything can be rolled back)
Principle: every change is small, attributed to a task, reviewed before it lands, and reversible by one documented command. Nothing is overwritten in place; history is append-only.

**Code (git).**
- `main` is protected by convention: only merges of reviewed branches; **no force-push, no history rewrite, no amend after push**.
- One branch per agent task: `feat/<role>-<task-id>`, where `<task-id>` is the heading in `docs/progress.md` (e.g. `T014`). Agents work in their own git worktree so they never touch each other's files.
- Small commits, one logical change each, message `T014 backend: add SAM candidate endpoint`. Author = the user's git identity only. Each commit body lists files touched and how to verify.
- Merge only after a review file exists (`docs/reviews/…`) and the branch passes `pnpm test`, `pnpm build`, `check_clean.sh` locally. Squash is not used (keeps the trace).
- **Daily tags** `day-1` … `day-7` on `main` at end of day, plus `checkpoint-oct30`, `checkpoint-oct31`, `freeze-nov2`, `submitted`. Rewind = `git revert <sha>` (preferred, keeps history) or `git checkout -b recover day-4`.
- `docs/progress.md` entries link task → branch → commits → review file → deployment URL, so anything can be traced from a symptom to the change that caused it.

**Deployments (Vercel).**
- Every push produces an immutable preview deployment; production is promoted explicitly, never auto-deployed from `main` during the hackathon (`vercel promote`). Rollback = Instant Rollback / `vercel rollback` to the previous production deployment, under a minute.
- `vercel.ts`, env var names, and function limits live in the repo; env *values* are pulled, never committed. `docs/deployments.md` logs each promotion: date, deployment URL, git tag, who approved, and the rollback target.
- The demo URL used in the video is pinned to a specific deployment alias (`demo-nov3`) so later changes cannot break what judges see.

**Database (Neon + Drizzle).**
- Schema changes only via generated migrations in `web/drizzle/` with a written down-path note; migrations are applied by a script, never by hand. No destructive migration (drop/rename) without a backup branch first.
- **Neon branching**: a `pre-<migration>` branch before every migration and a `demo-content` branch after seeding; restore = switch `DATABASE_URL` to the branch or use Neon point-in-time restore. Seeds are idempotent and re-runnable.
- Soft deletes only (`deleted_at`) for creators, artworks, products, orders; nothing is hard-deleted during the event.

**Assets (Blob).** Write-once paths with content hashes (`…/cleaned-<sha8>.png`); a new version is a new path and the DB pointer moves. Nothing is overwritten or deleted during the event; `scripts/gc.ts` exists but is never run before Nov 9.

**AI calls (the part judges and we will want to inspect).**
- Every model call goes through `lib/ai/trace.ts`: writes an `ai_calls` row `{id, job_id, stage, provider, model, request_hash, request_json (redacted of media bytes), response_id, response_json, latency_ms, cost_estimate, created_at}` and links it to the artwork/listing it produced. Agent loops store the full step list (`agent_trace`, `shaping_trace`). Every artwork keeps the Muse Image `response_id` chain so any variant can be regenerated or continued.
- `/admin/trace/[artworkId]` renders the chain (transcript → shaped prompt → variants → description → selection → mask → sticker) for debugging and for the demo's "how it works" shot.
- Fixtures recorded from real calls make any stage replayable offline and deterministically testable.

**Design.** Canvas versions are immutable on the artifact side; each daily sync records the canvas version id in `docs/decisions.md` next to the token diff. `design/tokens.json` is versioned in git, so a design rewind is a git revert of one file plus the generator run.

## 3. Meta modules (`web/lib/meta/`, all `server-only`, wrapped in `withFixture(name, fn)` for `META_FIXTURES=1`)
- `client.ts`: `meta = new OpenAI({baseURL:'https://api.meta.ai/v1'})`, `MODELS` map. (Ollama client for Glimmer lives in `lib/ai/ollama/`; the Baseten client in this line is superseded.)
- `transcribe.ts`: `transcribe(audio: Blob, lang?)` via `fetch` multipart to `/v1/asr/transcribe` (confirm field names day 1).
- `image.ts`: `generateVariants(prompt, n=4)` parallel Responses calls with style suffix "single subject, centered, flat colors, bold outlines, plain pure white background, no text, no shadow"; `refine(prevResponseId, instruction)`; `editFromDrawing(cleanedUrl)` optional enhance (never default; preserve the artist's lines). Extract image from `image_generation_call` output item `.result`.
- `sam.ts`: `findAll(image, phrases)` → phrases "drawing" + "object" (T080) return **all** matches as candidates `{id, bbox, maskUrl, thumbUrl, score}` for the Adjust-cutout screen; `segment(image, {candidateIds|points(with label)|box})` for the adjustment; streaming, parse `response.output_text.delta`, stop on `response.completed`; `finishMask` (fill holes, close, soft 8-bit edge) then `removeBackground(png, mask)` via sharp alpha join + trim. Fallback: threshold mask (ink on paper only; last resort).
- `sticker.ts`: `offsetMask(mask, mm=3, dpi=300)` = blur+threshold dilation (merges islands, rounds corners like a real die-cut); `traceOutline()` with potrace JS → single bezier path; `composeSticker()` → 300 dpi PNG (white fill under outline, 1.5 mm bleed, `withMetadata({density:300})`) + die-cut SVG (magenta stroke). `ensureDpi()` Lanczos ×2 if short side < 900 px. **Muse Code slice.**
- `mockup.ts`: Muse Image compose (artwork PNG + `public/ref/tote.jpg`) → product photo on white studio background.
- `shape-prompt.ts`: `shapePrompt(transcript, prefs)` Spark strict JSON `{prompt, style_notes, clarifying_question|null, spoken_confirmation}`; if a clarifying question comes back, iOS shows it as text (VoiceOver announces it) and records the answer, then re-calls with both turns. Trace stored in `artworks.shaping_trace`.
- `describe.ts`: Spark vision strict JSON `{alt_text, spoken, dominant_colors[], subject, differences_from_prompt}`; `differences_from_prompt` drives the "does this match your idea?" refinement loop.
- `listing-agent.ts`: `runListingAgent(productId)` Responses tool loop with `check_resolution`, `check_contrast` (sharp luminance stddev + edge ratio), `suggest_price` (rule table: sticker $4–7, tote $22–30, + complexity), `moderate_content` (Spark second call), `finalize_listing`; ≤8 iterations, forced final strict-JSON call if no finalize; every step → `listings.agent_trace`.
- `story.ts`: `draftStory(transcript)`, `draftThankYou(transcript, buyerName, productTitle)` via Muse Glimmer on Ollama (`OLLAMA_BASE_URL`, OpenAI-compatible chat completions, `response_format: json_schema`); 20 s timeout, logged fallback `provider:'fallback'` to Spark 1.3 (always the path on Vercel).
