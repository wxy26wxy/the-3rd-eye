### Concerns judged
1. **`color.scrim` is now ink at 55 %.** Acceptable.
   - `rgba(17,24,39,0.55)` is exactly what `color-mix(in srgb, var(--primary) 55%, transparent)` produced, so no web pixel changes.
   - Measured worst-case white-on-panel contrast over the real photos at 390: shop hero 5.18:1; Welcome headline panel 7.37:1, promises panel 5.42:1, footer pill 7.18:1. All are above 4.5:1. The value is photo-dependent: over pure white it would be 4.2:1, so the token's use stays limited to the photos it was measured on (the existing rule).
   - `pnpm tokens` regenerates `ios/App/Theme/Tokens.swift` byte-identically: no diff after the run.
   - The iOS readers on `feat/ios-T103` are covered in N1.
2. **Kebab-cased space names.** Acceptable, and more consistent than before.
   - `pnpm tokens` followed by `git diff --stat` shows no change.
   - Every CSS custom property in `web/app/tokens.css` is already kebab-case: `--type-display-xl-*`, `--radius-*`, `--shadow-*`. The pre-existing space names are single lowercase words, so the change leaves them byte-identical, and the new multi-word ones (`--space-card-pad`, `--space-block-l`, `--space-gutter-wide`, `--space-band-l`) follow the same style as types and radii. There are not two styles in CSS.
   - Swift keeps camelCase (`Tokens.Space.cardPad`), as it does for every other group.
   - It is a one-line change in a design-lane file; mention it to the design lane when merging.
3. **Value-based `rem` allow-list.** Acceptable for now.
   - Today the only spacing literal that rides on the allow-list is the chip's `padding: 0.25rem`, and `docs/design/tokens.md` lists it by name with its board node. The `2rem` in `Pages.module.css` is the documented check-circle size used in a centring calc.
