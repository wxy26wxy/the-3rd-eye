## Findings

### Minor 1: optional Spark call is serial and shares the full 90 s model timeout
`web/lib/pipeline/artworks.ts:271`, `web/lib/ai/meta/describe.ts` (`subjects`)
The call is bounded: `MetaDescriber` defaults to `metaResponses()` (`web/lib/ai/meta/client.ts:58-61`), which passes `callSignal(CALL_TIMEOUT_MS)` (90 s, inside the request deadline, one SDK retry). But it runs before SAM, not alongside it, and it is optional. A hung Spark call can burn most of the request budget before the default SAM phrases start, and the failure is then swallowed as a warning, so the user waits and gets the old result.
Why it matters: latency on the main upload path, plus "Use this area" (see Minor 2).
Fix: pass a short per-call limit for this call, e.g. `this.responses.create(body, { signal: callSignal(15_000) })` (the `ResponsesLike` options already allow it). Optionally start the two default SAM phrases in parallel with it. Not required for merge.

### Minor 2: "Use this area" (`detectInBox`) now also pays the Spark call and re-orders
`web/lib/pipeline/artworks.ts:331`, `:262-290`
`segmentInBox` is shared by the upload path (`previewFramedCut`, `createFromImage`) and `detectInBox` (Adjust the area, T134). Round 2 therefore adds one Spark call and the frame-filling-last order to every re-frame, not only to the first upload. In a tight frame around one piece with distinct parts, the auto-cut is now the largest part named by Spark, not the whole piece the user framed. This follows ruling item 3 and the whole piece stays in the strip, so it is within spec; it is worth the PM knowing and watching in the live check.
Fix (only if the PM wants it): pass an option from `detectInBox` to skip subjects when the box is smaller than the photo.

### Minor 3: no test for a malformed `subjects` answer
`web/test/subjects-t153.test.ts`
Code path is correct: `parseJsonOutput` throws on bad JSON, `cleanSubjects` returns `[]` for a non-array or non-string items, and `segmentInBox` catches and warns (`[subjects] ...`). Only the failing-call case (c) and the happy parse (e) are tested.
Fix: add a case with `output_text: "not json"` (expects a throw from `MetaDescriber.subjects`) and one with `{subjects: "plant"}` (expects `[]`).

### Minor 4: other test stubs lack `subjects`, so the warning path runs there
`web/test/detect.test.ts:50` (and the `describer` stubs in `change-artwork.test.ts`, `artwork-adjust.test.ts`)
The stub has no `subjects`, so `registry.describer.subjects(...)` throws a TypeError that is caught and logged as a warning. This is acceptable, and I found no test that passes only because of it: the changed `detect.test.ts` assertions concern ordering and options of the SAM stub, which is independent of the subjects call. It does add a `[subjects]` warning to test output and hides a real regression if the call were removed.
Fix: add `subjects: async () => []` to the `detect.test.ts` stub.
