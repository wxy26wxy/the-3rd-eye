## Issues

### Critical

### Important
1. **"See a story tag in action" publishes a real buyer's story tag.** `web/lib/db/queries.ts` `getDemoStoryTagToken`.
   - What: the query picks the newest order of any published product by a public example creator with a story video. The seed creates no orders (`scripts/seed.ts` has none), so that token always belongs to a real order: one placed by the team, a tester or a judge on the deployed site.
   - Locally the link resolved to `/t/<token>`, a live order for Leo. Its page carries the order's private thank-you area and an open "Send a note" form (`name="body"`).
   - Failure scenario: every shop visitor who follows the link lands on that buyer's tag. The page's client `tap` adds one to that order's `tapCount` per view. Any visitor can post into the buyer↔creator thread as if they held the tag, which notifies the creator. The next real thank-you the creator sends to that buyer is shown to the public.
   - The query never reaches a hidden or deleted creator (`creators.hidden = false`, `isExample = true`, `deletedAt` null, story video present, product published and not deleted, order and token not deleted). The problem is the order itself, not the creator.
   - Fix (no migration):
     - Pin the demo to a dedicated example order, either through a config constant or env var holding a demo token created once by the team, or a seed or admin step that creates a demo order.
     - Filter the query to that token, so no real purchase can be picked.
     - Optionally render `/t/<demo>` without the note form and the tap.
     - Until then, falling back to `/how-it-works#story-tags` is the safe default.

### Minor
2. **One architecture claim says more than the live run shows.** `docs/architecture.md` (T111 edit row) says "three changes on photo pieces… each followed by `cutout`". In the T123 live run (task-123-report Part B), the sticker path made one change and cut it out. The tote path made two changes ("petals orange", then "stem green" via Change it again), and only the last one was cut out. Fix: "three changes (one a Change it again on a change result); `cutout` on the two that were used".
3. **"Half of every sale goes to the artist." is the default, not a guarantee.** `web/messages/en.json` `shop.heroTrust`. A creator with a custom split would make it inaccurate, and the product page's new split line already shows the real share. Optional: "By default, half of every sale goes to the artist."
4. **A partial custom split can add up to more than 100 %.** `web/lib/split.ts` `splitPercents` fills each missing field from the default independently, so `{creator_bps: 6000}` alone renders 60/30/20 = 110 %. `creators.split` is `NOT NULL` with a complete default, so this needs bad data. Optional: use the default as a whole when any field is missing.
