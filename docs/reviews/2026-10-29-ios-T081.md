## Issues

### Critical

### Important
1. **`simpleMode` is now permanently on for new creators, and the docs say it can be changed when it can't.** References: `ios/App/Networking/Models.swift:13` (default `true`), `web/lib/db/schema.ts:56-57` (server default `simpleMode: true`), `docs/accessibility.md:21` and `:29`, `docs/decisions.md` (new ADR), `docs/handoffs/ios.md` T081 section.
   - What: the iOS settings sheet was the only UI that could turn `simpleMode` off, and the web has no toggle. `grep` of `web/` finds `accessPrefs` only in the API route, the schema and `components/create/api.ts` (which reads `speakDescriptions` only).
   - Consequences for every new creator:
     - `DrawingYourIdeaView.swift:28` always asks for 1 variant, never 3, so the multi-picture pager and VoiceOver script step 6 cannot happen.
     - `ListingDetailsView.swift:92` always runs AI prefill on its own.
     - `CameraView.swift:64` always opens the camera on its own.
   - The docs say `simpleMode` is "still honoured when the creator turned it on on the web" and that the web uses the `accessPrefs` toggles. Both are false.
   - Why it matters: this is a silent product change. The brief assumed a web setting that does not exist, and the implementer did not flag it.
   - Fix: correct the three docs to say that `simpleMode` defaults on and no client can change it right now. Then raise it with the controller: either the web gets a toggle, the default changes, or iOS stops reading it. Don't change the behaviour inside T081 without a decision.
2. **Story talking points can be announced twice.** Reference: `ios/App/Screens/Listing/StoryVideoView.swift:83`.
   - What: `prompts` starts as `defaultPrompts`, so `.announces` posts the defaults on appear. The `.task` then replaces them with the fetched prompts (`:81`), which changes the text, so it posts again a moment later. That cuts off or repeats the first announcement.
   - Why: the brief says to announce once. VoiceOver users hear the wrong set first, then the real set.
   - Fix: announce after the fetch settles. For example, drop `.announces` and post once at the end of the `.task`, whether the fetch succeeded or fell back to the defaults. Or gate it with a `loaded` flag (`.announces(loaded ? prompts.joined(...) : nil)`).
3. **With several pictures, the image's VoiceOver label is probably not the alt text.** Reference: `ios/App/Screens/Create/VoiceResultView.swift:34` vs `:74`. Not verified on a device.
   - What: in the multi-variant branch, the `TabView` has `.accessibilityLabel("Picture n of N. Swipe…")` and is not its own accessibility element. In SwiftUI, a label on a container like this is usually applied to the child elements, which would replace the per-picture `accessibilityLabel(altText)` that T081 added. I could not test this path, because the mock (and, per issue 1, every new creator) has `simpleMode` on and gets 1 variant. The single-variant path is fine.
   - Why: the brief requires that the image gets `accessibilityLabel(altText)`. Step 5 of the VoiceOver script also says the picture reads its alt text.
   - Fix: check it with the Accessibility Inspector using a mock answer that has `simpleMode: false`. If the label is overridden, move the position text into an `accessibilityValue` or hint on the pager, or append it to each picture's label ("altText, picture 1 of 3").

## Deviation: sign-out button in place of the gear
This is the right call. Removing SettingsView as written would have left TestFlight testers with no way to sign out. The button is an `IconButton` (48 pt, label "Sign out", hint "Asks before signing you out"). It asks before signing out (`confirmationDialog` with a destructive "Sign out" and a "Cancel"), and `AppState.signOut()` clears the token, orders, flow and path.

It leaks nothing sensitive. The version, git sha and server URL were already shown in the old settings sheet. They are a public build hash and the public deployment URL, not tokens or keys. The display name belongs to the signed-in person.

Two small gaps:
- The Create tab (the default tab after sign-in) has no button. That is acceptable, because the other three tabs have it, and the ADR records it.
- Issue Minor 3 above.
