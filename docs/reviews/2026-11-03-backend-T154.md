## Findings

### Minor 1. `docs/api.md` still describes the old rule (`docs/api.md:128`, rows at `:197` and `:203`)
Line 128 says "a **box** or any **positive** point adds one SAM object ... unioned with the candidates". With `candidateIds` that is no longer true for a box: only a positive point (or a box with no `candidateIds`) asks SAM. Row 197 ("`box` -> one SAM object ... unioned with the piece") has the same drift for the case of marks that are negatives only, and row 203 says "SAM runs on the edited picture" without the exception. The clients are unaffected: the Add-area request (points + box) still reaches SAM, and no client sends a box-only request. The API reference should still match the server. Fix: reword line 128 to "any **positive** point, or a **box** when no `candidateIds` are sent, adds one SAM object ...; with `candidateIds` a box only clips (`clipToBox`)", and adjust rows 197 and 203 in the same way. A docs-only line can ride on this branch or the next.

### Minor 2. ADR and progress wording misstate the fragment size (`docs/decisions.md` T154 entry; `docs/progress.md` T154 entry)
The decision text says fragments of "1-2 % of a percent", which reads as 0.01-0.02 %. The brief's evidence is candidates covering 0.01-0.02 **of the crop**, which is 1-2 %. A fragment at 1-2 % is at or above the 1 % threshold (`area >= frameArea * 0.01` keeps it), so the rule removes only fragments below 1 %, not the ones the evidence names. This is the PM's ruling and the tests match it, but the live check should confirm the strip actually loses the pencil/mug bits; if the 1-2 % fragments survive, the threshold is the knob, not a bug here. Fix: correct the wording to "fragments of 1-2 % of the crop" and note that the threshold removes those below 1 %.

### Minor 3. The report is stale (`.superpowers/sdd/.../task-154-report.md`)
It names only `c24da84`, says "Concerns: none" and lists the first-round rule ("SAM for positive points only"). The final state is `ad6ee13` with the amended rule. Fix: update the report before filing (hash, rule, test count).
