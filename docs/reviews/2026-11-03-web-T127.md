### Minor (optional)
1. **Two tabs can mislabel the cache.** `web/components/create/store.ts` (`save`).
   - What: `save` stamps the cache with the cookie's *current* id, but the in-memory `state` was restored under the id that was current at load. Cookies are shared across tabs; `sessionStorage` is per tab.
   - Scenario: tab 1 is signed in as A with a loaded draft, and tab 2 signs in as B. Tab 1's next save writes A's draft and profile under B's id, and a reload of tab 1 then restores A's draft for B.
   - This needs two tabs and two creators on one browser, which is rare for a studio kiosk but possible.
   - Fix: remember the id `state` was loaded under; in `save` (or `load`), drop the state when the cookie id differs.
2. **`POST /api/v1/auth/code` sets the token cookie but no sign-in id.** `web/app/api/v1/auth/code/route.ts:17`.
   - The web flow signs in through `/create/code/session`, so today nothing is affected (no web caller found in `components/create`).
   - If a browser client ever used the JSON route, its cache would stay keyed to "no id". Optional: set the id there too, or note it in the handoff.
3. **The pill clearance uses a fixed height.** `web/components/product/Product.module.css` `.mainImage > .slideContain`.
   - `max(12%, var(--space-xxl) + var(--size-min-target))` assumes the pill ends at about 54 px. With a large browser text size the pill's text grows, so its height can exceed that and it could again overlap the top of a tall sticker.
   - Optional: express the clearance in `em`/`rem`, or measure the pill with a CSS variable shared by `.tagPill`.
