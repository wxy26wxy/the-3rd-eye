## Judgement of concern 1 (Your cutout keyboard path)
The concern is valid but, with the fact that T113 keeps the piece strip and per-piece buttons, it is a documentation-accuracy issue, not a product blocker. Raising it was the right call (copy-v3-ios.md:86 and :103 give conflicting signals about whether the strip survives on "Your cutout"), and the "record what the build offers" step is a reasonable hedge while T113/T114 were in flight. What docs/accessibility.md should state once T113/T114 merge:
- Web "Your cutout" / "Fix the edges": the mode radio group (Add area, Remove area, Draw a box) plus the three per-piece buttons per strip item, "Box around this piece", "Add the area around this piece", "Leave this piece out", are the keyboard and screen-reader path; they need no pointer or drag. Expected reading per button includes the piece number and result (for example "Added area, mark 1"), and the status region announces the mark and "Mark removed" on delete. Tab order: strip, mode group, marks list, Apply cutout, Use this, Start over.
- iOS "Your cutout": the pieces strip stays; each piece exposes the same actions as accessibility actions or buttons (use whichever T114 shipped, with the exact labels), the mark can be deleted with the "Deletes this mark" action, and "Apply cutout" announces "Your cutout is ready. Here it is."
- Remove the "if none, blocker" branch; replace it with a pass/fail line for the tester ("all three edge actions reachable without touching the photo").
- Keep the stated gap "not yet run on a device" until it is.
