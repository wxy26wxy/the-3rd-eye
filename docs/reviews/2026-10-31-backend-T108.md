### Minor
- **M1 · Preview and print can disagree on how many pieces there are.** `web/lib/image/sticker.ts:139`.
  - What: `previewCutPath` sets its border to 3 % of the cleaned PNG's short side. `composeSticker` uses 3 mm at 300 dpi after `ensureDpi` (35 px, after an upscale of up to 2×). Before T108 both always gave one contour, so the gap was only in line width. Now the merge decision can differ.
  - Measured with two bars:
    - 3000 × 1500 with a 64 px gap: print 2 contours, preview 1.
    - 600 × 600 with a 33 px gap: print 1 contour, preview 2.
  - Why it matters: the product page tells the buyer one sticker while two pieces are cut (or the other way round). This happens only when pieces are about 4–6 mm apart, and the print files themselves are right.
  - Fix: in `previewCutPath`, use the print border in the cleaned PNG's pixels: `k = short >= 900 ? 1 : min(2, 900 / short)`, `borderPx = max(4, round(mmToPx(BORDER_MM) / k))`. Add one test that the preview and the print give the same subpath count for a gap near the threshold.
- **M2 · "Closer than 2 × border merge" is about 1.6 × in practice, and near-touching cut lines are possible.** `web/lib/image/sticker.ts:107`, `docs/api.md:75`.
  - What: `dilate` (blur σ = r/2, threshold 5) grows a straight edge by 28 px for r = 35, so islands merge only up to a gap of about 56–58 px, not 70.
  - Failure scenario: fixture (c) has a 60 px gap and its two cut lines are only a few px apart, under 1 mm. A die cut that close can tear the sliver between the pieces.
  - Fix:
    - Option 1: close the offset mask with a small extra radius before tracing (dilate by border + s, erode by s), so cut lines are never closer than s. This is a print-spec decision for the PM.
    - Option 2: at minimum, change the docs to "about 1.6 × the border".
- **M3 · With an expired local OIDC token, some private reads return "not found" instead of the new 503.** `web/lib/storage/blob.ts:181-185`, `:68`.
  - What: when OIDC is missing, the SDK (`resolveBlobAuth`) silently uses `BLOB_READ_WRITE_TOKEN` for `{ storeId }` calls. `head`, `del` and `get` take that token and run against the public store. In `signedUrl`, `exists()` answers not-found from the public store, so `/media` returns 404 instead of 503. `putPrivate`'s `exists()` probe also reads the public store.
  - Nothing private is written publicly: `put` with `access: "private"` is refused, which is the observed error. So this costs clarity only, not privacy.
  - Fix (local only, so Vercel is untouched): when `!process.env.VERCEL`, the creds carry no token and `oidcTokenState()` is not `ok`, throw the 503 from `privateCreds` callers before any SDK call.
- **M4 · The 503 message names a CLI command to API clients.** `web/lib/storage/blob.ts:29`.
  - On Vercel the credential is automatic, so this message appears there only if the store is misconfigured. It leaks no values, but an iOS creator or a `/media` caller would read "run `vercel env pull`".
  - Fix: return a neutral message to the client ("Storage is unavailable; try again later") and keep the CLI hint in the one-time log. Acceptable as is for the hackathon.
- **M5 · `BuyState` is typed but not a discriminated union.** `web/app/(site)/p/[id]/actions.ts:9`.
  - What: `error` without `field` type-checks, and the form treats it as `form` (`web/components/product/BuyForm.tsx:19`). That behaviour is safe.
  - Fix: `{ values?: … } & ({} | { error: string; field: BuyErrorField })` would let the compiler enforce that every failure says where it goes. Optional.

### Concerns judged
- **(a) Pieces 4.7–6.5 mm apart now print as one sticker. Acceptable.**
  - On a roughly 3 in (76 mm) sticker, separate pieces under about 6 mm apart are fiddly to peel. Two cut lines 0–2 mm apart (the previous outcome in that band) tear or leave slivers.
  - The merged outline keeps the 3 mm border on every outer edge, and the white bleed fills the bridge.
  - It is a spec change, so it belongs in the print checklist, and the docs already state it. No action beyond the PM noting it.
- **(b) The lost refresh path is real; the trade is acceptable for now.**
  - In `@vercel/oidc` 3.8.10, `getVercelOidcToken` (`get-vercel-oidc-token-with-refresh.js`) is what `@vercel/blob` 2.8.2 calls. When the env token is missing or expired, it calls `refreshToken()`: it finds `.vercel/project.json` by walking up from `cwd`, gets a CLI auth token (keyring, or `auth.json` with an OAuth refresh) and fetches a new OIDC token into `process.env`. So `vercel env pull` is not the only refresh: with a linked checkout and a logged-in CLI, the SDK would have recovered on its own.
  - The main checkout has `web/.vercel/project.json`, so the refresh could work there. This worktree has no `.vercel` directory, so it could not; that fits the T105 failure.
  - The trade costs only local convenience (one `vercel env pull`) and nothing on Vercel.
  - Better, as a follow-up: in the local branch of the check, first `await getVercelOidcToken()` from `@vercel/oidc` (add it as a direct dependency) and throw the 503 only if that fails.
- **(c) The implementer counted variable names in `.env.local` to confirm `VERCEL` is unset locally**, without reading values. Noted; no action.
