### Important
1. **The Welcome footer link fails contrast.**
   - Where: `web/components/create/Create.module.css:489-490` (`.welcomeLinks`), rendered by `web/components/create/SignOut.tsx:22` (and `:19` for Sign out).
   - What: the "I already have an account" / "Sign out" text action is white 15 px text placed straight on the sky photo, with no scrim. I measured it the same way as the scrim panels at 390×844: worst 2.45:1, mean 2.58:1. WCAG 1.4.3 needs 4.5:1.
   - Why it matters: this is the only Sign out on the web creator flow (ruling 5) and the only sign-in entry on Welcome. The decisions entry justifies the 55 % scrim with "15 px white text needs 4.5:1", and then leaves this 15 px line off any scrim. The board draws it the same way, but the brief makes accessibility a requirement, not polish.
   - Failure scenario: a low-vision creator on a phone in daylight cannot read or find Sign out, or cannot find "I already have an account".
   - Fix (pick one): give the link a scrim pill (`color-mix(--primary 55%)`, radius pill, 44 px); or put it inside the promises scrim panel; or use a dark ink link on a white pill. Then re-measure to at least 4.5:1, and log it in `docs/decisions.md` as a deviation from the board.
2. **The live end-to-end flow has still not been run on this branch.**
   - What: the implementer drove every state with stubs (report concern 2). I could not sign in either, for these reasons:
     - `web/.creator-codes.local` has no "Test Artist" line, only the three seeded public creators.
     - Reading the hidden creator's code from the database was refused by the session's permission policy (credential access).
     - I chose not to sign in as a public demo creator, because Listing approval publishes to the public shop.
   - Why it matters: the brief names the real SAM photo path, the Blob upload and the story-video upload as untested. T105 re-plumbed submits through `form` attributes (code, Speak, Listing) and moved Select rendering. All of that works with stubs, but nothing has shown it against the real BFF.
   - Fix: before merge (or as the first step of the v0.7-rc1 smoke), the PM or the user runs the flow with the Test Artist's code: Pick sticker → Upload `test/fixtures/generate/probe.png` → Finding → Select (piece, positive mark, Apply cutout, reload to check the saved cut survives, Use this) → Ready → Listing approve → Story video Skip → Live. Then soft-delete the artwork from My designs.

### Minor
1. **Focus is lost on several in-page transitions.** In each case the focused control unmounts and focus drops to `<body>` (checked live):
   - Speak "Type instead": `Speak.tsx:154`, focus → BODY.
   - Result "Change it" and the panel's "Back": `Result.tsx:92`, `:141`, focus → BODY both ways.
   - Listing "Put it in the shop": the button becomes disabled and focus → BODY. After the 409 the card is announced (`role=alert`), but keyboard users restart from the top.

   This is mostly pre-existing (the base Result had no focus handling), but T105 moved more controls in and out of the bar. Fix: on these transitions, focus the new field, the "Use this" button, or the error card (the error wrapper needs `tabIndex={-1}` plus `.focus()`, as Select already does with `errorRef`).
2. **The MP4 still downloads under reduced motion.** `ui/Mascot.tsx:25` uses `preload="auto"` and `autoPlay` on a video that CSS hides under reduced motion, so the 147 KB file is fetched and unused. The visual behaviour is right. Fix: `preload="none"` plus a `matchMedia` check, or a `<source media>`-style switch.
3. **Result reads the description up to three times.** `VariantPicker.tsx:25` and `Result.tsx:97` put the description in the radio name, the tile image alt and the preview alt, on top of the visible "What the image shows" card. This is a logged deviation; it is verbose but not a regression. Fix: tile images `alt=""` (the radio gets its name from "Picture n"), and preview alt = description, or `alt=""` now that the card is visible.
4. **Two controls named "Back" in the Result change panel.** The top-left link goes to `/create/speak` and the panel text action `Result.tsx:141` is also "Back". To a screen-reader user they look the same and do different things. Fix: give the panel button a more specific name, or an `aria-label` such as "Back to the pictures" (needs an en.json key).
5. **Pre-existing: Listing "Try again" re-runs the wrong call.** On a 5xx from approve, `ListingView.tsx:99` (`onRetry={on.improve}`) re-runs the listing agent instead of re-submitting. The behaviour predates T105 (same at base), but T105 now owns this view. Fix: pass a retry that matches the failed call, as Select does with `failed`.
6. **Speak gives no feedback while the mic prompt is open.** Live, pressing record left `navigator.permissions` at "prompt" with the button unchanged. If the person also taps "Type instead" and then grants access, `startRecording` resolves and sets `phase="recording"` while the text form is open. This is an edge case. Fix: ignore the result of `recorder.start()` once `typing` is true.
7. **Unchosen pieces in the strip are not dimmed.** The board shows them dimmed (`2027:3254` Piece 3); the shot shows them at full strength. This is cosmetic.

## Concerns judged
1. Expired `VERCEL_OIDC_TOKEN` -> 500 "Cannot use private access on a public store". `web/lib/storage/blob.ts` `privateCreds()` returns `{ storeId }` when `BLOB_PRIVATE_STORE_ID` is set and relies on the SDK to find OIDC. When the token is expired, the SDK fails with the message the implementer saw. Defer to a follow-up, not this branch: (a) a server-side fallback to `BLOB_READ_WRITE_TOKEN` would put private artwork into the public store (hashed path), which the file's own design reserves for "store id absent" and which weakens the privacy model; it should not be done silently. (b) A cheap safe improvement is to catch this specific SDK error in `putPrivate` and throw an `ApiError` with a clear, non-production-looking message ("Local credentials expired: run `vercel env pull`") only when `NODE_ENV !== "production"`. On Vercel the credential is automatic, so users of the deployed app are not affected. Record in docs/architecture.md (env section) that the local token lasts about 12 h. Not an app defect for T105.
2. One upstream 503 from the listing agent, Try again succeeded. Out of scope: backend/upstream. The UI behaved as designed (error card, M5 retry repeats the failed call). Worth a backend note about the 42 s time before failing; not this branch.
3. Product-page die-cut dashed path wrapping only one piece of a two-piece cut. Pre-existing, not caused by this branch: `git diff main...HEAD` touches neither `components/site/DieCut.tsx` nor `lib/image/sticker.ts`; the path comes from `traceOutline(cut)` in `lib/image/sticker.ts:131`, and the shot (14) shows a red dashed path around only the fern, offset from it, while the mockup above is correct. Defer to T106 (product page) or a backend ticket; note the dashed path also looks misaligned (it is a box-like blob, not the contour), which suggests a scale or viewBox problem in the preview, worth including in that ticket.
