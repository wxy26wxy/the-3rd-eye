## Install on your iPhone (deployed site)
1. On the Mac: `cd ios && xcodegen generate && open The3rdEye.xcodeproj` (needs Xcode and `brew install xcodegen`).
2. Plug in the iPhone (unlock it, tap "Trust"). On the phone turn on Settings → Privacy & Security → Developer Mode if asked, and restart it.
3. In Xcode select the **The3rdEye** target → **Signing & Capabilities** → Team: your Apple ID ("Personal Team"; add it under Xcode → Settings → Accounts if missing). If the bundle id `com.the3rdeye.app` is taken, change `PRODUCT_BUNDLE_IDENTIFIER` in `ios/project.yml` to something unique like `com.<yourname>.the3rdeye` (`BrandIdentityTests.testBundleIdentifier` compares the built bundle id with `project.yml`, so it keeps passing).
4. Pick **Product → Scheme → Edit Scheme… → Run → Build Configuration: Release**, so the app talks to the deployed site, `DEPLOYED_SITE_URL` in `ios/project.yml` (Debug also talks to the deployed site since the 2026-10-29 decision; switch it to `http://localhost:3000` by hand only for a local server). To use another deployment, set Build Settings → User-Defined → `API_BASE_URL` (Release) to its https URL.
5. Choose the phone as the run destination and press **Run**. First time only: on the phone open Settings → General → VPN & Device Management → your Apple ID → Trust, then open the app.
6. In the app: on My designs, Orders or Messages, the sign-out button (top right) shows the version and server URL in its confirmation; tap Cancel to stay signed in. Sign in with your creator code (codes are issued per creator and are not in the repo). Allow camera and microphone when asked; if you said no, the app shows an "Open Settings" button.
7. Check on the phone: record a story video (captions need the soundtrack, which the app now sends), accept or edit the drafted story, send a thank-you with a short video. Free provisioning expires after 7 days; press Run again to renew.

## Build and run
```
cd ios
xcodegen generate
xcodebuild -project The3rdEye.xcodeproj -scheme The3rdEye -destination 'platform=iOS Simulator,id=<sim id>' -derivedDataPath build/DerivedData build
xcodebuild test -project The3rdEye.xcodeproj -scheme The3rdEye -destination 'platform=iOS Simulator,id=<sim id>' -derivedDataPath build/DerivedData -resultBundlePath /tmp/t3e-unit-$(date +%s).xcresult
xcrun simctl boot "iPhone 17"; xcrun simctl install booted build/DerivedData/Build/Products/Debug-iphonesimulator/The3rdEye.app; xcrun simctl launch booted com.the3rdeye.app
```
Server: build setting `API_BASE_URL` (Debug and Release default `$(DEPLOYED_SITE_URL)`, the production site set once in `project.yml`; `http://localhost:3000` only by override; empty or invalid falls back to it through Info.plist `DeployedSiteURL`), e.g. `xcodebuild ... API_BASE_URL=https://<deployment> build`. Only `localhost` has an ATS exception; any deployed server must be https. On a physical phone `localhost` is the phone itself, so point it at the deployment.
Without the backend: `python3 scripts/mock_api.py` (port 3999) and build with `API_BASE_URL=http://localhost:3999`. UI tests (photo first: Adjust the area, Change it, Before and after, Your cutout, Making your sticker; My designs; deep link):

Pick the simulator by id (`xcrun simctl list devices available | grep "iPhone 17 Pro ("`; several share the name) and uninstall the app first for a fresh install (`xcrun simctl uninstall <sim id> com.the3rdeye.app`). Always pass `-project The3rdEye.xcodeproj` (an old ignored project file sits next to it). ## Interface exposed to others
- Calls exactly the routes and field names in `docs/api.md`. Upload pathnames: `creators/<creatorId>/{photos|story-video|thank-you-images|thank-you-videos|audio}/<uuid>.<ext>`; the token request carries `clientPayload` `{"kind": "<folder>"}`.
- Story video and thank-you video requests carry `audioUrl` (pathname of `creators/<id>/audio/<uuid>.wav`, 16 kHz mono 16-bit PCM, ≤ 30 s / 15 s) when the video has sound.
- Reads optional `Creator.storyDraft` (`{ headline?, bio_short|bioShort?, story_text|storyText? }` or a string) from the story-video answer or `GET /creators/me`; "Use" sends `PUT /creators/me { storyText }`.
- Any 401 on a request that carried the token signs the app out (token expiry). Long calls wait 300 s.
- Photos are uploaded as JPEG without EXIF/GPS/TIFF metadata.
- Photo artworks are created with the Blob `url`; videos are sent as Blob `pathname`.
- `POST /listings/{id}/run` is sent with an empty JSON object body.

## Adjust cutout (T082)
- `App/Screens/Create/AdjustCutoutView.swift` (route `.adjustCutout`, replaces Tap to select). Pieces are toggled in the thumbnail strip; numbered labels on the photo mark them but take no taps (T091, so a mark can go on a label). VoiceOver sees only the strip (checkbox: label "Piece n", trait selected, "Not selected" value when off); the labels are hidden from it so each piece is read once. Mode control "Add area / Remove area / Draw a box": "Add area" taps add positive marks, "Remove area" taps add negative marks, which drop the whole chosen piece they land on (server rule); to trim one piece, draw a box around what should stay. A negative mark that would leave nothing (it lands on the only chosen piece, no box, no positive mark) is refused with that advice, and a cleanup with "Remove area" marks answered 422 shows the same advice (other 422s show the server's message; T083). Tap a mark's 24 pt dot to delete it (≤ 10); a tap anywhere else adds a mark, so marks can sit next to each other; one gesture layer takes every touch on the photo (marks and labels take none; VoiceOver gets each mark as a button whose action deletes it). Only the picture is clipped, so a mark at the edge overhangs the frame. In "Draw a box" a UIKit pan (`BoxDragSurface`) draws the box, so the drag wins over the screen's scroll view; "Clear marks" removes both. Retake drops the photo, its pieces, marks and box (`CreateFlow.discardPhoto`).
- VoiceOver / Switch Control path: each piece in the strip has the actions "Box around this piece" (box = its bbox), "Add the area around this piece" (positive mark at the bbox centre) and "Leave this piece out"; the same actions are in its context menu (long press), which the UI test uses because XCUITest cannot run VoiceOver custom actions. The mode buttons and the instruction tell VoiceOver users to use those actions.
- **"Apply cutout" is a commit, not a throwaway preview:** `cleanup` saves the new cut on the server (and rebuilds, possibly unpublishes, products made from the artwork). On success the app sets `flow.artwork` and `flow.cutoutNotice` at once and shows the cut on a `Checkerboard` with "Back to photo" / "Show the cutout". "Use this" then just goes on (no second call unless the pieces or marks changed). In redo mode "Use this" with nothing changed goes straight back, and a single piece is sent as `cleanup {candidateIds: [id]}` (not `select`) so product notices arrive.
- While a request runs, Back, Retake, the chips, the marks, the mode control and Clear marks are disabled; the request keeps running if the screen disappears (another tab; T083), writes into the flow it started with, and the screen navigates only if it is still the top of its path (redo is captured when the request starts).
- Coordinates: `CutoutGeometry` maps view ↔ `imageSize` pixels (`fitRect` inside the photo frame, clamped); a 0 × 0 `imageSize` is ignored. State lives in `CreateFlow` (`imageSize`, `selectedCandidateIds`, `points`, `box`; `resetCutout` on each new photo answer selects the only piece when there is one).
- Redo: Design ready shows "Adjust cutout" when `flow.photoArtwork` is the shown artwork; the screen then has no step pill and no Retake, and "Use this" pops back. Without a local photo or `imageSize` it loads `GET /artworks/{id}` and shows `originalUrl` (an error if that fails).

One product could not be rebuilt; try again later."; `unpublishedProductIds` → "One product went back to draft because the new cutout is too small to print. Open My designs to fix it." (`CleanupResult.productNotice`, shown on the screen and on Design ready). Chosen `candidateIds` are sent with every points/box edit.

- **Outfit's default instance is Thin (wght 100).** The bundled `Outfit-Variable.ttf` registers the family "Outfit" with Thin as its default; any text that reaches the font without a weight renders Thin. T114 must (1) apply `ThemeFont.body` (the `TextRole.body` font) as the environment default font at the app root, so a `Text` without an explicit role still gets Outfit Regular, and (2) add a unit test that asserts every `ThemeFont` / `TextRole` role resolves with a weight ≥ 400 (`Font.Weight.regular` or heavier, via `TextRole.weight` and `Tokens.TypeWeight`). `ThemeEffectsTests.testOutfitIsRegistered` stays as is (registration only).
