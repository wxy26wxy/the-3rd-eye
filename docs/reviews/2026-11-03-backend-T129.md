## Issues

### Important (recommendations for T130/T131 and a small follow-up; not blocking this branch)
1. **Step 9's "whole-picture box" also makes the server ask SAM for an object. On a Remove-only edit, that can add instead of remove.**
   - What: `cleanupArtwork` treats any `box` as "add one SAM object prompted with the box and all points", then unions it with the piece. Only after that does it clip (`web/lib/pipeline/artworks.ts:366-374`). With `box = [0,0,w,h]`, the clip does nothing, and SAM's object for the full frame is unpredictable.
   - Why the tests don't show it: the T129 test of this case stubs SAM to return `null` ("nothing found here"), so the risk is invisible there.
   - Failure scenario: the creator taps "Remove area" once on the tail. The client sends the piece, one negative point and the whole-picture box. SAM returns a large region around the main subject, and the union grows the cut beyond the piece.
   - Fix, either or both:
     - (a) Docs, now: step 9 should say "the frame (the cut's bbox with a margin) or, only when adding, the whole picture".
     - (b) Server, a small rule: when `clipToBox` is true and every point is `negative`, use the box only as a clip and skip the SAM call. This is also the T126 follow-up about a redundant SAM call. Pin it with one test in which SAM *would* return a big object.
   - Confirm either way in the first live run.

## Step 9 rule and server default
- **The client rule is right:** send `candidateIds: [candidates[0].id]` (more precisely, the current selection, initially `candidates[0]`) together with the marks. Without it, the cut is only SAM's box-plus-points object and the auto-cut piece is lost, which is correct server behaviour for a body without candidates.
- **Recommendation: do not default it on the server.** The server does not store which candidate is the current selection (`queries.contract.ts`: "Which SAM candidate was chosen is not stored"). A silent default to `candidates[0]` would re-add a piece the creator already removed, if a client sends a later edit without ids. It would also make "points + box without candidateIds" (a deliberate fresh SAM cut, which T129 tests) behave differently on a change result than on any other row. Keep the request explicit and document it, as done.
- If a guard is wanted later, the safe one is to answer `400 invalid_request` "send the current piece" when a change result that has candidates receives only negative points and no `candidateIds`, since nothing would be left to remove from.
