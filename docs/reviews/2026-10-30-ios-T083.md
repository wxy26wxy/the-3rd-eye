## Issues

### Critical
1. **"Leave empty to keep it" silently changes a live listing's price.** `ios/App/Screens/Home/EditListingSheet.swift:32,55-62,68`. When the price field is empty, `priceCents` is omitted. The server then does `price = edits.priceCents ?? existing.priceSuggestionCents ?? product.priceCents` (`web/lib/pipeline/products.ts:191`). `priceSuggestionCents` is the agent's suggestion and is never overwritten by an earlier approve (`upsertListing({...existing, …})` keeps it). Take a creator who listed at $8 against a $5 suggestion (Listing details always sends `priceCents`). If they rename the listing in Edit listing, the live price drops to $5 with no warning. The sheet, the ADR and the api.md note all claim the empty field keeps the current price. The mock hides this because its `approve` returns `edits.priceCents or 500`.
   *Fix:* the client cannot read the current price, so make the price required in the sheet. A better fix: ask backend to add `priceCents` to `ArtworkProduct`, or make `approve` prefer `product.priceCents` for a published product, then prefill the field. Correct the ADR, api.md and the handoff, and add a mock case where the suggestion and the live price differ.

### Important
2. **R2 and R4 have no test.** The brief says "each with a test". R1 has a unit test and two UI tests, and R3 has a UI test. Nothing switches tabs during a cleanup (R2). Nothing checks that "Leave this piece out" is missing from an unselected piece (R4). The context menu mirrors that rule, so a UI test can long-press an unselected strip item and assert the button is absent.
   *Fix:* add a UI test for R4. For R2, add a UI test: Apply, switch to My designs, switch back, assert the applied view or `flow.artwork`. Or add a unit test on `record(_:in:)`.
3. **Edit listing on a draft is a second, weaker publish path.** `DesignDetailView.swift:113-119`, `EditListingSheet.swift:37-38,69-72`. A draft with a title gets "Edit listing", and its sheet button reads "Save and list it". The "Save and list it" label is honest, but this path:
   - ignores `storyVideoNeeded`, so a first listing published here never reaches the Story video step that `ListingDetailsView:150` pushes;
   - skips You're live;
   - starts with an empty price, so the server picks the suggestion (see 1).

   A creator who only wants to fix a typo on a draft cannot do so without publishing it.
   *Fix:* for a draft product, route "Edit listing" to `continueFrom(artwork:productType:)` (Listing details, the existing publish flow), and keep the sheet for published products only.
4. **"Make a sticker" on a design already in the shop makes a duplicate product without saying so.** `DesignDetailView.swift:105-111`, `MyDesignsView.swift:28-32`, `AppState.swift:153-166`. Only a draft is reused. With a published sticker, the button still reads "Make a sticker", with the hint "Makes a sticker and writes its listing". It goes to `POST /products`, and in simple mode Improve runs automatically (an AI call), producing a second sticker listing. This is the d1 case the UI test opens. The report and ADR list it as known, but the creator gets no signal.
   *Fix:* when a published product of that type exists, hide the button, relabel it "Make another sticker" with a confirmation, or point to Edit listing / See it in the shop.
5. **A reused draft opens Listing details with an empty price and a disabled Approve button, with no reason given.** `ListingDetailsView.swift:81-89`, `AppState.swift:158-161`. `continueFrom` builds `Product(id:artworkId:type:status:)` without `priceCents` or `mockupUrl`, so `fill(from:)` leaves the price empty. When the draft has a title, Improve is skipped. "Approve and list it" is then disabled (`:39`), and the only message, "Add a name and a price first…", is posted only from an enabled tap. The description field is also empty even though the server has one, and approve keeps it unseen. The UI test checks the name only.
   *Fix:* show the "add a price" hint when the button is disabled, or run Improve when the price is unknown. Say in the description field that an empty value keeps the saved text. The real fix is the same backend read as in issue 1.
6. **Context-menu actions are not mirrored as accessibility actions on the tile.** `MyDesignsView.swift:26-36,75-78`. The tile is `.accessibilityElement(children: .ignore)` with only a hint ("Long press for more."). "Make a sticker" and "Delete" are not added with `.accessibilityActions`, as the brief asks. The UI test helper notes that the context menu makes each tile appear twice in the query (`DesignsUITests.swift:119`), which suggests VoiceOver may also see two elements per tile.
   *Fix:* add `.accessibilityActions { Make a sticker; Delete }` to the tile. Check with Accessibility Inspector that each tile is one element.

### Minor
7. **"Cutting out…" with a spinner for up to 10 minutes on a photo that is waiting for a choice.** `DesignsStore.swift:18,24` and `DesignDetailView.swift:69` ("Still cutting it out. Come back in a minute."). The server answers within 270 s. Clarification 5 says a row with no cut, no error and several candidates is "waiting for a choice", not cutting. The badge is also computed at render time with no refresh, so a tile keeps spinning until the next load.
   *Fix:* use a 5-minute window, and offer "Re-do the cutout" as the call to action in that state.
8. **A redo from My designs opens with nothing selected.** `DesignDetailView.swift:151-157`. Unlike `resetCutout` on the Create path, nothing is selected, even for a single piece. So `savedRequest` is `.some(nil)`, "Use this with nothing changed goes straight back" can never happen from My designs, and leaving through "Use this" always re-cuts on the server, which rebuilds products and may unpublish them.
   *Fix:* call `flow.resetCutout(candidates:imageSize:)` (or preselect the single piece) when opening the redo.
9. **A 404 or archived product after a delete elsewhere leaves a stale tile.** `DesignDetailView.swift:159-162,171-173`, `EditListingSheet.swift:73-75`. Re-do shows "Artwork not found" and Delete shows the same 404. Edit shows "This product was removed with its design" (409 `product_archived`). In each case the tile stays until the next load.
   *Fix:* on `404 not_found` from `GET`/`DELETE /artworks/{id}`, or on 409 `product_archived`, call `designs.load()`. For DELETE, also treat a 404 as already deleted.
10. **`GET /artworks` runs on every visit.** `MyDesignsView.swift:42`. `.task` re-runs on every tab switch and every pop back to the grid, and `leave()` adds another load (`AdjustCutoutView.swift` `leave`). Loads are not coalesced, so a load already in flight can briefly bring back a tile that was just deleted. This is cheap and harmless for a demo.
    *Fix:* skip the load if one ran in the last ~30 s, or cancel the previous load before starting a new one.
11. **Delete shows no progress.** `MyDesignsView.swift:138`, `DesignDetailView.swift:165-175`. The dialog closes at once, the detail's buttons stay enabled during the DELETE, and a second Delete or "Make a sticker" can be sent in that window.
    *Fix:* add a `deleting` state that disables the actions.
12. **The client accepts prices the server rejects.** `EditListingSheet.swift:58`. It accepts any price above 0, but the server takes 100..100000 cents and titles up to 80 characters. The answer is a 400 whose zod message is not creator-friendly.
    *Fix:* check `cents >= 100` and the title length on the client.
13. **The detail picture for a design with no image reads its badge twice.** `MyDesignsView.swift:101-102` with `DesignDetailView.swift:44-47`. VoiceOver hears "Didn't work" from the picture and again from the badge.
    *Fix:* hide the placeholder from VoiceOver on the detail screen.
14. **The detail's cut-out notice never clears.** `DesignDetailView.swift:97-99`. `cutoutNotice` stays on `designFlow` and shows on every later visit to that design. After Apply without Use this, the product badges are stale until a reload.
15. **`continueFrom` discards a creation in progress in the Create tab without asking.** `AppState.swift:162`. This contradicts the ADR's reason for `designFlow` ("a creation in progress in the Create tab is not overwritten").
    *Fix:* confirm when `createPath` is not empty.
16. **Docs.**
    - `docs/handoffs/ios.md:93` (T082 section) still says "a cleanup answered 422 shows the same advice", which R1 changed.
    - `docs/decisions.md:127`: the T083 ADR has no blank line before its heading, and it states the price assumption that is wrong (issue 1).
    - `docs/api.md` "Client assumptions" item 3 needs the same correction.
    - The mock covers none of the 409s (`print_check_failed`, `moderation_failed`, `product_archived`) and no 404 after a delete. The approve error path is untested.
