## Install on your iPhone (deployed site)
1. On the Mac: `cd ios && xcodegen generate && open The3rdEye.xcodeproj` (needs Xcode and `brew install xcodegen`).
2. Plug in the iPhone (unlock it, tap "Trust"). On the phone turn on Settings → Privacy & Security → Developer Mode if asked, and restart it.
3. In Xcode select the **The3rdEye** target → **Signing & Capabilities** → Team: your Apple ID ("Personal Team"; add it under Xcode → Settings → Accounts if missing). If the bundle id `com.the3rdeye.app` is taken, change `PRODUCT_BUNDLE_IDENTIFIER` in `ios/project.yml` to something unique like `com.<yourname>.the3rdeye` (`BrandIdentityTests.testBundleIdentifier` compares the built bundle id with `project.yml`, so it keeps passing).
4. Pick **Product → Scheme → Edit Scheme… → Run → Build Configuration: Release**, so the app talks to the deployed site, `DEPLOYED_SITE_URL` in `ios/project.yml` (Debug also talks to the deployed site since the 2026-10-29 decision; switch it to `http://localhost:3000` by hand only for a local server). To use another deployment, set Build Settings → User-Defined → `API_BASE_URL` (Release) to its https URL.
5. Choose the phone as the run destination and press **Run**. First time only: on the phone open Settings → General → VPN & Device Management → your Apple ID → Trust, then open the app.
6. In the app: on My designs, Orders or Messages, the sign-out button (top right) shows the version and server URL in its confirmation; tap Cancel to stay signed in. Sign in with your creator code (codes are issued per creator and are not in the repo). Allow camera and microphone when asked; if you said no, the app shows an "Open Settings" button.
7. Check on the phone: record a story video (captions need the soundtrack, which the app now sends), accept or edit the drafted story, send a thank-you with a short video. Free provisioning expires after 7 days; press Run again to renew.

## Build and run
```
cd ios
xcodegen generate
xcodebuild -project The3rdEye.xcodeproj -scheme The3rdEye -destination 'platform=iOS Simulator,id=<sim id>' -derivedDataPath build/DerivedData build
xcodebuild test -project The3rdEye.xcodeproj -scheme The3rdEye -destination 'platform=iOS Simulator,id=<sim id>' -derivedDataPath build/DerivedData -resultBundlePath /tmp/t3e-unit-$(date +%s).xcresult
xcrun simctl boot "iPhone 17"; xcrun simctl install booted build/DerivedData/Build/Products/Debug-iphonesimulator/The3rdEye.app; xcrun simctl launch booted com.the3rdeye.app
```
Server: build setting `API_BASE_URL` (Debug and Release default `$(DEPLOYED_SITE_URL)`, the production site set once in `project.yml`; `http://localhost:3000` only by override; empty or invalid falls back to it through Info.plist `DeployedSiteURL`), e.g. `xcodebuild ... API_BASE_URL=https://<deployment> build`. Only `localhost` has an ATS exception; any deployed server must be https. On a physical phone `localhost` is the phone itself, so point it at the deployment.
Without the backend: `python3 scripts/mock_api.py` (port 3999) and build with `API_BASE_URL=http://localhost:3999`. UI tests (voice branch: the confirmation text on the loading screen and the "WHAT THE IMAGE SHOWS" card with the description on Voice result; deep link):
`TEST_RUNNER_MOCK_API_URL=http://localhost:3999 xcodebuild test -project The3rdEye.xcodeproj -scheme The3rdEyeUITests -destination 'platform=iOS Simulator,id=<sim id>' -derivedDataPath build/DerivedData -resultBundlePath /tmp/t3e-ui-$(date +%s).xcresult API_BASE_URL=http://localhost:3999`
Pick the simulator by id (`xcrun simctl list devices available | grep "iPhone 17 Pro ("`; several share the name) and uninstall the app first for a fresh install (`xcrun simctl uninstall <sim id> com.the3rdeye.app`). Always pass `-project The3rdEye.xcodeproj` (an old ignored project file sits next to it). Always pass a new `-resultBundlePath`: on Xcode 27.1 with iOS 27, `xcodebuild test` without one can hang after the last test, printing `IDESchemeActionSDKRecord … invalidDigitCount` forever (T091). The UI tests live in the `The3rdEyeUITests` scheme; `-only-testing:The3rdEyeUITests/...` on the `The3rdEye` scheme fails.
On a phone: see "Install on your iPhone" above. No entitlements are used.
UI tests now include `AdjustCutoutUITests` (photo branch). To run the mock on another port (another server may hold 3999 on IPv6, which `localhost` then reaches first and sign-in fails with "That code did not work"), start it with the port and run `TEST_RUNNER_MOCK_API_URL=http://localhost:<port> xcodebuild test … API_BASE_URL=http://localhost:<port>`: the first is an environment variable of the `xcodebuild` process (passed to the test runner as `MOCK_API_URL`), the second a build setting.
The mock also answers `POST /creators/me/story-video` (logs `audioUrl`, returns a `storyDraft`) and `POST /orders/o1/thank-you`.

## Interface exposed to others
- Calls exactly the routes and field names in `docs/api.md`. Upload pathnames: `creators/<creatorId>/{photos|story-video|thank-you-images|thank-you-videos|audio}/<uuid>.<ext>`; the token request carries `clientPayload` `{"kind": "<folder>"}`.
- Story video and thank-you video requests carry `audioUrl` (pathname of `creators/<id>/audio/<uuid>.wav`, 16 kHz mono 16-bit PCM, ≤ 30 s / 15 s) when the video has sound.
- Reads optional `Creator.storyDraft` (`{ headline?, bio_short|bioShort?, story_text|storyText? }` or a string) from the story-video answer or `GET /creators/me`; "Use" sends `PUT /creators/me { storyText }`.
- Any 401 on a request that carried the token signs the app out (token expiry). Long calls wait 300 s.
- Photos are uploaded as JPEG without EXIF/GPS/TIFF metadata.
- Photo artworks are created with the Blob `url`; videos are sent as Blob `pathname`.
- `POST /listings/{id}/run` is sent with an empty JSON object body.

## Adjust cutout (T082)
- `App/Screens/Create/AdjustCutoutView.swift` (route `.adjustCutout`, replaces Tap to select). Pieces are toggled in the thumbnail strip; numbered labels on the photo mark them but take no taps (T091, so a mark can go on a label). VoiceOver sees only the strip (checkbox: label "Piece n", trait selected, "Not selected" value when off); the labels are hidden from it so each piece is read once. Mode control "Add area / Remove area / Draw a box": "Add area" taps add positive marks, "Remove area" taps add negative marks, which drop the whole chosen piece they land on (server rule); to trim one piece, draw a box around what should stay. A negative mark that would leave nothing (it lands on the only chosen piece, no box, no positive mark) is refused with that advice, and a cleanup with "Remove area" marks answered 422 shows the same advice (other 422s show the server's message; T083). Tap a mark's 24 pt dot to delete it (≤ 10); a tap anywhere else adds a mark, so marks can sit next to each other; one gesture layer takes every touch on the photo (marks and labels take none; VoiceOver gets each mark as a button whose action deletes it). Only the picture is clipped, so a mark at the edge overhangs the frame. In "Draw a box" a UIKit pan (`BoxDragSurface`) draws the box, so the drag wins over the screen's scroll view; "Clear marks" removes both. Retake drops the photo, its pieces, marks and box (`CreateFlow.discardPhoto`).
- VoiceOver / Switch Control path: each piece in the strip has the actions "Box around this piece" (box = its bbox), "Add the area around this piece" (positive mark at the bbox centre) and "Leave this piece out"; the same actions are in its context menu (long press), which the UI test uses because XCUITest cannot run VoiceOver custom actions. ## Sky components (T103)
Every screen reads these; screens never draw their own buttons, cards or headlines. Values come from `Tokens` (generated) or `ThemeEffects` (Theme.swift).
- `DisplayText(key, role: .displayXL, alignment: .leading, onPhoto: false)`: Inter Medium 48 ink (Bold white with `onPhoto`), header trait. `tilted:` is accepted and ignored.
- `PillButton(title, hint:, kind:, showsArrow:)` / `PillButtonStyle`: `.primary` 56 pt ink pill with the 48 pt arrow circle; `.onPhoto` white pill on photos; `.secondary` 50 pt white pill with a 1 pt border and a centred label. Disabled = `Theme.Opacity.disabled`.
- `Card(selected:, padding:)`: white, or accent with `accentBorder` when selected; 28 radius, 1.5 pt border. `ChoiceCard`: a Card button with `RadioMark` top-right (selected trait for VoiceOver). `MethodRow(icon:, name:, detail:, eyebrow:, highlighted:)`: Choose-how-to-make-it row (44 pt icon tile, name, description, chevron), label "name, detail".
- `IconButton(systemName: or asset:, label:, hint:, size:, mirrored:)`: outlined white circle; 48 pt default, 44 pt (`Theme.Size.minTarget`) for Back and Sign out.
- `LogoMark(onPhoto:)`: 40 × 35 eye mark, decorative.
- `TagMascot(pose: .book | .front | .magnifier, size:, label:)`: photo mascot; `.magnifier` loops `mascot-magnifier.mp4` muted (still `mascot-front` with Reduce Motion). Decorative unless `label` is set. `SkyCard(pose:)` (in LoadingScreen.swift): the 342 × 286 card with the mascot.
- `FlowScreen(title:, subtitle:, step:, showsBack:, trailing:, pinsActions:)`: white page; Back (44 pt, VoiceOver "Back") when `showsBack`, else the logo mark; headline, description and content scroll; the actions are pinned in the bottom `ActionBar` (`.actionBar { … }`, also usable on any screen; `onPhoto:` for the Welcome photo). `pinsActions: false` puts a long action list after the content instead (Design detail). `step` is only a VoiceOver hint ("Step n of 3").
- `TabScreen(title:)`: logo mark + Sign out (identifier `sign-out`), headline, content. `LoadingScreen`: logo mark, headline, SkyCard, I HEARD card, message, spinner; error = card + Try again / Go back. `ErrorCard`: white bordered card, 44 pt Try again.
- `HomeTabBar`: see `docs/decisions.md` (T103). The host exposes one accessibility element per tab; the VoiceOver reading is to be confirmed on a device (`docs/accessibility.md`). Tabs keep the labels Create / My designs / Orders / Messages and `app.tabBars.buttons[...]` in UI tests.
- Retired, draw nothing (remove the call sites in T104): `StepPill`, `Starburst`, `ScallopDivider`, `CreamSheet` (now just page padding), `GrainOverlay`, `.hardShadow`.

### Adding an image or animation
1. The design owner adds the file to `design/assets/` and an entry to `design/tokens.json` `assets` (`template: true` for single-colour icons), then from the repo root (Node 24) `pnpm tokens && pnpm assets`: PNG/SVG land in `ios/App/Assets.xcassets/<name>.imageset/` and `Tokens.Asset.<name>` is generated; a GIF becomes `ios/App/Resources/Animations/<name>.mp4` (needs `ffmpeg`).
2. In code: `Image(Tokens.Asset.<name>)` (`.renderingMode(.template)` + a token colour for icons; `.resizable().scaledToFit()` for photos), or `LoopingVideo(resource: Tokens.Asset.<name>)` for an MP4, with a still image when `accessibilityReduceMotion` is on. Decorative images get `.accessibilityHidden(true)`; meaningful ones a label.
3. `ThemeEffectsTests.testAssetsAreBundled` checks every non-pending asset is in the app; run `xcodegen generate` so a new folder under `Resources/` is picked up.
