## Findings

### 1. Minor · `web/lib/pipeline/story-video.ts:211` · the "mp4" check also accepts QuickTime .mov files
`checkProbe` accepts any `format_name` that lists `mp4`. ffprobe reports the same string (`mov,mp4,m4a,3gp,3g2,mj2`) for .mp4, .mov, .m4v and .3gp, so an H.264/AAC .mov passes as "an mp4". The file is then stored with a `.mp4` pathname and `video/mp4`. Browsers usually play it, but the brief says "H.264/AAC mp4". Why it matters: low (the founder's file is a real mp4). Fix: either also check `format.tags.major_brand` (`isom`, `mp42`, `avc1`, `M4V `, not `qt  `), or check the file extension in `parseStoryVideoArgs`, or word the check as "an MP4-family container" in the README. The test pins only the happy `mov,mp4,…` string and a Matroska refusal, so a `qt` case could be added with the fix.

### 2. Minor · `web/test/story-video-t151.test.ts` · a few behaviours are not pinned
The 12 tests pin real behaviour (call order, exact update payloads, flag-only `mentionDisability`, null captions on failure and silence, route warnings, dry run writing nothing, stop before any write). Not covered:

- the glue in `web/scripts/story_video.ts` (INIT_CWD resolution, the ENOENT message, the temp-dir `finally`).

I exercised the glue by hand, read-only (see below) and it behaves as intended, so this is about regression protection, not a defect. Fix: add the first three as short cases; the script glue can stay untested, as for the other scripts.

It also says "the full text in the T151 report", but the report does not contain the text.
