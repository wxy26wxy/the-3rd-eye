## Strengths
- **Flow matches the boards and `docs/api.md` (T111).** `/create` → product → method (photo / upload only; a stale `voice` draft counts as no choice, `ChooseMethod.tsx:16`) → photo → `/create/pattern` (GET `artworks/{id}` via `useOriginal`, single-pick radio strip, POST `select`) → `/create/change` → `/create/changing` (POST `artworks/{id}/change`, `transcript` sent only when the spoken text was not retyped, any 2xx accepted) → `/create/compare` → `/create/cutout` → `/create/making` → ready / listing / live. Old routes redirect (`speak`, `drawing`, `result` → `/create/method`; `select` → `/create/pattern`).
- **R2/R3 are modelled cleanly in the store** (`web/components/create/store.ts:142-180`). `currentChange` / `currentArtworkId` / `backToOriginal` / `addChange` / `pieceCutout` are small, pure and unit-tested. Checked in the browser with a stubbed BFF: "Change it again" POSTs to the child (`POST artworks/ch1/change`), and "Back to my original" switches to the parent with no request. "Looks good as is" on the picked piece reuses the cut-out that `select` already made (no call). On a change result, `cutout` is called first (`MakingCutout`, `YourCutout.tsx:45-81`). This matches `docs/api.md` §T111 item 1 and Before and after board `2027:3091`, which has Use this / Change it again / Back to my original and no "Looks good as is". "Looks good as is" sits on Change it (`2027:3138`) and leads to Your cutout, not straight to making. That is the documented contract.
- **Draft resets are thorough.** A new photo clears every piece/change/cutout field (`Photo.tsx` `NEW_PIECE`). A new `select` clears changes and cutout. Start over keeps only `product`. Ready "Not now" and Live "Make another" call `resetDraft()`.
- **Error states follow the boards.** A change 502 `edit_failed` falls to "The change did not work this time." with Try again / Back to my art (seen in the browser). A failed transcribe shows the error card with Try again, plus Looks good as is / Try a different change (`2038:4060`). Mic denied switches to the typed path: mic-off hint, status notice, field, Make the change, and the Looks good as is text action (seen in the browser). Cutout `422 no_drawing_found` opens Fix the edges in box mode. `409 not_a_change` (stale drafts only) shows the server reason with Back to my art.
- **Copy:** 25+ rows checked verbatim against `docs/design/copy-v3-web.md`: Welcome title/cta/haveAccount, method title, select title / copyMany / copyOne / groupLabel / instruction / needPiece / applied / backToPhoto / applying, cutout title / adjustCopy / copy / copyOriginal / makingTitle / makingCopy (+ original), making titleSticker / copySticker / titleTote / copyTote, drawing title / error / back, result title / youSaid "You asked" / before / after / change / backToPictures / skip / tryDifferent / titleEntry, speak title / hint / hintMicOff / textLabel / textPlaceholder / done / artLabel, ready.titleTote. The Welcome title uses the " / " line-break convention.
- **The Your cutout keyboard path is intact** (implementer concern 3, confirmed in the a11y tree at 390): checkbox strip "Piece n"; per piece, a group with "Box around this piece" / "Add the area around this piece"; the tool radios (Add area / Remove area / Draw a box); the instruction and the keyboard hint; "Use the whole photo" (no-pieces case); the Marks list as buttons ("Added area, mark 1. Remove this mark"); Clear marks; a polite live region ("Mark added"). Focus goes to the result heading after Apply and to the error after a failure.
- **Accessibility details:** the Before/After images carry the description as alt ("A green monster reads a red book."). The Change it art uses `alt=""` when the "What the image shows" card is next to it. The mic button has an accessible name ("Start talking") and a visible label. The field is labelled "What should change?". The sticker animation is decorative (`aria-hidden`); under reduced motion it is paused on frame 0 (checked: `paused: true, currentTime: 0, videoWidth: 320`).
- **Swappability:** raw-value grep = 4 (baseline set: ChoiceCard `1px`, PinnedBar `rootMargin`, globals.css ×2); rem grep = 0; no hard-coded UI strings in `components/create` / `app/create`; no provider imports.

## Issues

### Critical
None.

### Important
1. **"Back to my art" after a failed "Change it again" lands on Before and after, not Change it.** `web/components/create/screens/Changing.tsx:25-26` and `:69`.
   - What: the button is a Link to `/create/change` whose `onClick` clears `changeInstruction`. That makes `done = !changeInstruction && !!changedArtworkId` true, and the effect fires `router.replace("/create/compare")` after the Link's push.
   - Failure scenario (reproduced at 390 with a stubbed 502): piece → change → compare → Change it again → "Make it bigger" → 502 → "Back to my art" → the URL ends at `/create/compare` ("Here's the change"). The creator meant to retype the request.
   - On the first change (no `changedArtworkId`), the same click flashes MissingState ("start over") before the navigation lands.
   - Fix: compute the "already done, go to compare" redirect once on mount (for example `const [done] = useState(() => …)` in `Changing`). Alternatively, set a "leaving" ref in the button handler that suppresses the redirect, and navigate with `router.replace("/create/change")` before clearing the instruction. Add a PM test for it.
2. **Change it drops keyboard / screen-reader focus on every phase change.** `web/components/create/screens/ChangeIt.tsx:55-68`, `ChangeItView.tsx:56-99`.
   - What: each phase (idle → listening → transcribing → idle, mic off, error) renders a different tree, and nothing moves focus. Checked: after "Start talking" with the mic denied, `document.activeElement` is `BODY`.
   - Failure scenario: a keyboard user presses Start talking. The button unmounts, so Tab restarts at "Skip to content" and they must find Stop again. After transcribing, the transcribed text lands in the field, but focus is not there to review and submit it. Focus is also lost on the error and mic-off phases.
   - Fix: use the same `focusOn` pattern as `YourCutout.tsx:129-136`. Focus Stop when listening starts; focus the textarea after transcribing, after mic-off and on "Try a different change"; focus the error card on error. A ref on the field replaces the global `document.querySelector("textarea")` at `ChangeIt.tsx:67`.

### Minor
3. **Dead `create.*` keys remain (none are reachable).** `web/messages/en.json`: `create.speakInstead` ("Speak instead"), `create.speak.shaping`, `redo` ("Say it again"), `youSaid` ("You said"), `questionTitle`, `answerLabel`, `answerSubmit`, `answerSpeak` ("Answer out loud"), `hearAgain`; `create.drawing.spoken`; `create.result.changeLabel`, `changeSubmit`, `changePlaceholder`, `changing`.
   - Some are "unchanged" rows in the copy doc for the clarifying-question board (`2026:3098`), which is not built (concern 1). `create.result.variant` is now gone (`a4ec697`).
   - Fix: delete them, or keep the Question set on purpose and note that in the handoff. `create.drawing.spoken` ("Changing your art now.", a PM default) was meant to be spoken on Changing but is never used; either wire it in at the start or drop it.
4. **Focus on route changes stays on `body`.** `web/components/create/CreateMain.tsx`, `CreateScreen.tsx`.
   - Every `/create/*` page has the same document title, so the Next route announcer has nothing new to say. Seen after "Back to my original" (focus `BODY`, h1 "Change your art?").
   - This predates T113 (same layout on main), but T113 adds six routes.
   - Fix: focus the h1 (with `tabIndex={-1}`) on mount in `CreateScreen`, or set a per-screen title.
5. **Re-picking the same piece keeps a stale change on screen.** `web/components/create/screens/ChoosePattern.tsx:49-51`.
   - The "same piece as last time" shortcut skips the reset of `changes` / `changedArtworkId`.
   - Scenario: change → compare → Back → Back to Choose a pattern → Use this on the same piece → Change it opens on the earlier change, not the piece.
   - Fix: `update({ changedArtworkId: undefined })` (or the full change reset) before `router.push` in that branch.
6. **The reduced-motion still depends on the browser painting frame 0.** `web/components/create/art.tsx:31-46`.
   - `StickerLoading` has no `poster`. iOS Safari ignores `preload="auto"`, so under reduced motion the 342 slot may stay blank there.
   - The brief named `MotionVideo`. The deviation is reasonable, because `MotionVideo` shows nothing under reduced motion, but the copy doc asks for the first frame.
   - Fix: check it in part B on iOS Safari. If the slot is blank, add a still asset (`ASSETS.stickerLoading` PNG) as `poster`.
7. **The recording-state live region mounts together with its text.** `art.tsx:68` (`<div role="status">` around the LISTENING card). Some screen-reader / browser pairs do not announce a live region inserted already filled. Fix: keep one persistent polite region on Change it (as `SelectView` does) and write "Listening" into it.
8. **The flow PMs are not unit-tested.** The view and store tests are real behaviour tests (element order, copy, alt, disabled state, store transitions; no snapshots). Nothing covers `Changing` / `ChangeIt` / `ChoosePattern` / `Photo` routing (issues 1 and 5 would have been caught). Fix: one or two PM tests with a mocked `api` and `useRouter`.
