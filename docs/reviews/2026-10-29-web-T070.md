## Important

1. **Migration 0003 is not applied to the shared DB, and every creators query now selects `hidden`.**
   - Files: web/lib/db/schema.ts:62, web/drizzle/0003_t070_creators.sql:1
   - Failure: merge to main → Vercel deploy → `/`, `/artists`, `/c/*`, sign-in and the iOS `POST /auth/code` all return 500 with `column "hidden" does not exist`. The implementer saw this locally.
   - Fix: apply `ALTER TABLE "creators" ADD COLUMN IF NOT EXISTS "hidden" boolean DEFAULT false NOT NULL` to the shared DB before merging (command in docs/handoffs/backend.md). Applying it first is safe for the current production code, because the column is additive with a default. Then run the live smoke from the brief: add a hidden Test Artist, sign in with ?c=, confirm absent from / and /artists, rotate, confirm the old code returns 401. Merge only after that.

2. **Slug de-dup fails for long display names.**
   - File: web/lib/db/queries.ts:96-97 together with web/lib/codes.ts:570-577
   - What is wrong: `uniqueSlug` truncates the base to fit `-N` in 40 characters. But the "taken" lookup only matches `slug = base OR slug LIKE base || '-%'` with the untruncated base. When `slugify(name)` is 39-40 characters, the existing `-2` slug starts with the shortened base, so the lookup never finds it.
   - Failure: add the same 40+ character name three times. The second gets `<38 chars>-2`. The third computes `-2` again, hits a unique violation on the slug, retries 5 times with the same candidate and shows "Could not save."
   - Fix: query `LIKE` on `base.slice(0, SLUG_MAX - 4)` (or on a prefix of the truncated base), or add each failed candidate to `taken` and recompute inside the retry loop. Add a unit test for the 40-character case that feeds in the previously generated `-2`.

## Considered and set aside
- **Auth bypass on the Server Functions:** each action checks the request header itself, and "disabled" (no password set) counts as unauthorized.
- **`siteOrigin` and a spoofed Host header:** it prefers `NEXT_PUBLIC_SITE_URL`. The header fallback uses the admin's own request, so an outsider cannot influence it.
- **Code echoed in errors:** every admin error is `c.error` or `unauthorized`. The sign-in failure redirects without the code. The `/auth/code` 401 message is static.
- **Code present in the server-action response and React state:** this is the intended one-time display. It is not persisted, not in the URL, and gone after a reload.
- **Neon's `detail` on a unique violation ("Key (login_code)=(…)"):** `safeErrorText` logs only the message and `cause.code`, not the detail.
- **Other `console.error(err)` calls** (setOrderStatus, tap, placeOrder): these paths do not carry login codes.
- **Old code rejected after rotate:** the code is replaced in place, and the lookup is exact-match on an uppercased value, which matches the alphabet.
- **Existing tokens surviving a rotate:** this is documented as a decision, with a per-creator token version named as the follow-up.
- **`/t/[token]` and checkout for hidden creators:** `getStoryTag`, `getPublicProduct` and `staged.ts` are unfiltered, as the ruling requires.
- **Hidden toggle cache staleness:** reads call `connection()`, so they are dynamic and `revalidatePath` is not load-bearing.
- **LIKE wildcards in the slug query:** slugs are `[a-z0-9-]` only, so `_` and `%` cannot appear.
- **Seed importing `@/lib/codes`:** the seed already uses `@/` imports under tsx, and its behaviour is unchanged (same alphabet and length).
- **The Switch posting "on":** it is a native checkbox, and the action compares against `"on"`.
- **Hidden creators signing in and using creator routes:** this is intended and documented.
