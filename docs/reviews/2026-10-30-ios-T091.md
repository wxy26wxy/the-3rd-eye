### Minor
1. **"Edit listing" on a draft now asks "This sticker is already in the shop".**
   - Where: `ios/App/Screens/Home/DesignDetailView.swift:177-183` with `ContinueConfirmation.swift:528-534`.
   - What is wrong: `editListing` on a draft now goes through `requestContinue`. When a published product of the same type exists (mock d6), `another` is true, so tapping the draft row's "Edit listing" opens a dialog titled "This sticker is already in the shop" with "Continue the sticker draft". Before this change it went straight to Listing details.
   - Why it matters: the creator asked to edit a draft and gets a duplicate-product warning.
   - How to fix: pass a flag from `editListing` so that only `replacesCreation` triggers a prompt. Add a UI test on d6's draft row.
2. **`testRetakeClearsMarks` would pass without the fix.**
   - Where: `ios/UITests/AdjustCutoutUITests.swift:313`.
   - What is wrong: `CameraView.use()` (`CameraView.swift:89`) and `FindingDrawingsView.swift:31` already call `resetCutout` on every new photo, so the test cannot fail on the old code.
   - Why it matters: low. The behaviour is right, and `testDiscardPhotoClearsMarksAndPieces` covers `discardPhoto`.
   - How to fix: optionally assert state right after Retake, before a new photo is used, or note the limit in the test.
3. **The box surface ignores `.disabled`.**
   - Where: `AdjustCutoutView.swift:261` and `:647` (`BoxDragSurface`).
   - What is wrong: SwiftUI `.disabled(work != nil)` does not reach a `UIViewRepresentable`'s gesture recognisers. During Apply, a drag in box mode still draws a live outline, which then disappears because `setBox` and `removeMark` guard on `work`.
   - Why it matters: a visual glitch only.
   - How to fix: read `context.environment.isEnabled` in `updateUIView` and set `view.isUserInteractionEnabled`.
4. **The button label and the hint disagree.**
   - Where: `DesignDetailView.swift:152`.
   - What is wrong: with a draft, the button still reads "Make another sticker" while its hint says "Goes on to your sticker draft", and the action continues the draft.
   - Why it matters: the brief asked only for the confirmation text, but the label now disagrees with the hint and the action.
   - How to fix: use "Continue the sticker draft" as the label in that case.
5. **Mark delete target is 24 pt (implementer concern b).**
   - Where: `AdjustCutoutView.swift:299`.
   - What is wrong: the target is below the project's 44 pt rule. It meets WCAG 2.2 2.5.8 (24 px minimum).
   - Why it matters: alternatives exist (Clear marks, VoiceOver/Switch Control button with a 48 pt frame), and the decision is recorded. A side effect: a tap 13–24 pt from a mark adds an overlapping mark instead of deleting, and that counts toward the 10-mark cap.
   - How to fix: accepted as is. Optionally show the 10-mark notice text earlier.
6. **The VoiceOver delete action on marks is untested.**
   - Where: `AdjustCutoutView.swift` `mark(...)`.
   - What is wrong: the delete action sits on an element with `allowsHitTesting(false)`. XCUITest taps synthesise touches, which hit the gesture layer, so the `accessibilityAction` path is never run by any test.
   - How to fix: needs a VoiceOver pass on a device, already listed as not verified.
7. **A parked T083 deferral is not mentioned.**
   - Where: `docs/reviews/2026-10-30-ios-T083.md:120` lists three deferrals.
   - What is wrong: T091 does two of them. "Reload on every visit" is neither done nor deferred in the T091 report, progress or handoff. It was not in the brief either.
   - How to fix: one line in the T091 progress "Unfinished".
8. **The `xcodebuild` hang workaround is not in the docs (concern g).**
   - Where: `docs/handoffs/ios.md:22-30` and `docs/progress.md` T091 Verify.
   - What is wrong: the report says `xcodebuild test` can hang without `-resultBundlePath`, but neither the handoff nor progress commands include it.
   - How to fix: add `-resultBundlePath <fresh path>` to the documented commands, with one line on why. (My runs passed with it.)
9. **`docs/api.md:137` is stale (concern f).**
   - What is wrong: it still says "`edits.description` is sent only when non-empty".
   - Judgement: leaving it was correct, because the file is outside iOS ownership. It is flagged in the handoff, decisions and progress. It needs a backend or docs follow-up task.
10. **The report's per-suite count is off.**
    - What is wrong: the report says AdjustCutout 15. My run has AdjustCutout 14 and Designs 15. The total of 33 is right.
