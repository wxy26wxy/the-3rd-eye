## Strengths
- **`edit()` follows the brief.** `web/lib/ai/meta/image.ts:30-36` (`editBody`) sends one user message `[input_text (instruction + KEEP_GUARD), input_image]` with `IMAGE_TOOL`. It goes through the shared `call()` → `traced("edit", …)` → `toGeneratedImage`. The guard now lives in one constant (`web/lib/ai/guard.ts`), shared by `refine`, `edit` and the admin trace. `ImageProvider.edit` (`web/lib/ai/types.ts:25-26`) and the fixtures provider (`web/lib/ai/fixtures.ts:61-67`, deterministic: a hash of the instruction plus a procedural mark) match each other. `test/image-edit.test.ts` replays the recorded live response and covers the no-image error.
- **The fixture is clean.** `web/test/fixtures/edit/probe-edit.json` holds only the model/response ids, a reasoning summary about a red circle, usage counts, a 128 px base64 PNG and `ig_redacted`. The request's data URL is replaced by a placeholder. No key, email, path or personal data.
- **`changeArtwork` (`web/lib/pipeline/artworks.ts:250-275`)** writes every field the brief lists: `source:'photo'`, `parentArtworkId`, `changeInstruction`, a trimmed `transcript` or null, `genResponseId`. The private original and the public preview go under `creatorPath(...)` (the existing convention). `previews` is added to `PUBLIC_KINDS` (`web/lib/media-access.ts:8`). After that it runs `describe` against the instruction, which fills `altText`, `spokenDescription` and `differencesFromPrompt`. The row is inserted only after the edit succeeds, so a failed model call leaves no orphan row. The squared-on-white input (`changeInput`, 10 % margin, ≤ 1024 px) is a careful touch, and so is the 409 when nothing has been picked.
- **Routes.** `change/route.ts` uses zod `instruction` trim 1–1000 and `transcript` ≤ 4000, `maxDuration = 300`, `getArtworkForCreator` (404 for someone else's or a soft-deleted artwork, as on every other route) and 201. `cutout/route.ts` also sets `maxDuration = 300`. Both routes are covered by the model rate limit (`lib/rate-limit.ts:21-24`) and by the BFF forwarder (`maxDuration 300`, generic path).
- **Migration 0004 is additive and idempotent.** It has three `ADD COLUMN IF NOT EXISTS` statements, `quantity integer DEFAULT 1 NOT NULL`, and no drop, rename or type change. `schema.ts` matches it (`changeInstruction`, `size`, `quantity.default(1).notNull()`). The journal and snapshot were added. `apply-migration.mjs` now prints a presence line for all four additive columns.
- **Order math lives in one place.** `orderLine()` (`web/lib/payments/staged.ts:29-42`) validates quantity (1–10, `MAX_QUANTITY`) and size (`resolveSize` against the registry; a tote rejects any size; a sticker defaults to `3in`). It computes `unitCents × quantity` and runs before any lookup side effect. The shares come from the total. Both entry points use it: the site action (zod enum + coerce) and `POST /public/orders` (passes `size`/`quantity` through). Older clients get 1 × 3 in at the listed price. `/t/[token]` is not touched. The admin table shows "4 in × 2" plus a sample-pricing line.
- **The voice filter is retired cleanly.** `ShopFilter` (`queries.contract.ts:24`) and the `listPublishedProducts` branch (`queries.ts:342-347`) are both gone. `Collection.tsx` and `FilterTabs.tsx` are one-line edits. The site test now checks `type=voice` is absent, and there is a new `shop-filter.test.ts`. `madeByVoice` is still written at `products.ts:136`.
- **The trace relabel needs no data-model change.** `ArtworkTrace` gains the derived `photo` and `changes[]` (built from the existing ancestor chain). `TraceView` shows the seven steps in the board order, and `take("edit", "generate", "refine")` puts the edit calls under "Edit instruction".
- **Docs.** The `docs/api.md` T111 section covers both routes, the input-picture rule, Before/after, the three client actions, the size table, the R4 note (Create intro plus the `refine` line), and the client rule "hide drafts without `cleanedUrl` whose `parentArtworkId` is set". `docs/architecture.md` has the model-map row and the live finding.

## Issues

### Critical
None.

### Important
1. **`cutout` re-cuts any row, including one with live products, and does not report it.** `web/app/api/v1/artworks/[id]/cutout/route.ts:13-18`, `web/lib/pipeline/artworks.ts:282-298`.
   - What: `cutoutArtwork` runs on any own row that has an `originalUrl`. It replaces `candidates` and then calls `cleanupArtwork` → `recut`, which rebuilds the files of every product on that artwork (`artworks.ts:83-95`; this can also unpublish one). The route throws away `failedProductIds`/`unpublishedProductIds`.
   - Why: R3 only needs `cutout` on a change result. For "Looks good as is" on the picked piece, the cut-out already exists from `select`. The mock accepts `cutout` on any id (`ios/scripts/mock_api.py:136`), so a client that wrongly calls it on the original will pass every mock run.
   - Failure scenario: an artwork has a published sticker. The creator opens it from My designs and goes through "Your cutout" with an app build that calls `cutout`. The published sticker silently becomes "the largest SAM piece", and its print files and mockup are rebuilt (or it is unpublished) without the creator seeing a word.
   - Fix (a few lines): in `cutoutArtwork`, throw `409 not_a_change` ("Only a changed picture needs a new cutout") unless `artwork.changeInstruction` is set. Add `|| (await listProductsForArtwork(id)).length > 0` if re-cutting a child that already has a product should also be refused. Mirror this in the mock (`cutout_artwork` answers 409 for ids that are not `ch<n>`) and add one sentence to `docs/api.md` §2. The same guard settles "re-cutting a child twice": a second cutout on a child with no products stays allowed and just replaces candidates and the cut.

### Minor
1. **`docs/api.md:155`: the error list does not match the code.** It says "`502/503` model failure with `artworkId` when the child row exists". A failed edit or a refusal (no `image_generation_call`, `image.ts:21`) is a plain `Error` → `toApiError` → `500 internal "Something went wrong"`, and no child row exists at that point. Only a missing key gives 503. Fix: either document `500 internal` (`artworkId` only when the describe step fails after the insert), or wrap the edit in `changeArtwork` and throw `502 edit_failed` with a short "We could not change it this time. Try different words." message. The second is better for the "Error" state on the Change it board.
2. **The mock answers 200 where the server answers 201 for `change`** (`ios/scripts/mock_api.py:421`). Every other mock route already answers 200, and clients accept any 2xx. Trivial fix if wanted: let a handler return `(201, body)` and have `_handle` honour a tuple. Not blocking.
3. **Mock `GET /artworks/ch<n>` leaves out the top-level `previewUrl`** that the server's `GET /artworks/{id}` now returns (`mock_api.py:149-154` vs `web/app/api/v1/artworks/[id]/route.ts:23`). A client that rebuilds "Before and after" from a GET behaves differently against the mock. Fix: add `"previewUrl": row.get("previewUrl")` to `change_detail`.
4. **`docs/api.md:174` says nothing on the site reads `madeByVoice`, but two components still do**: `web/components/product/ProductView.tsx:38` and `web/components/site/ProductCard.tsx:23` still render the chip (removed in T112). Fix: say "nothing reads it once T112 lands", or fold this into T112's doc pass.
5. **Admin trace "Photo and mask" mixes two pictures for a change child.** `queries.contract.ts:312` takes the root photo's `originalUrl`/`maskUrl`, while `candidates` are the child's cutout candidates (SAM on the edited picture). `TraceView.tsx:38` `take("segment")` collects the segment calls from the whole chain into this step. The admin view is readable but can mislead a judge who compares the candidates with the photo. Fix (optional): show the child's candidates under "Decision", or label them "Cutout pieces".
6. **The auto-pick can land on a sub-part** (`artworks.ts:288-289`). `findCandidates` drops a "container" (> 40 % of the frame that contains a higher-scoring result). On a white-background edit the whole piece can easily cover more than 40 %, so it could be dropped in favour of a part, and the largest remaining part is then auto-picked. The edge tools can recover this, and SAM's threshold fallback covers "nothing found" (422 only when the fallback is empty too). Check it in the first live change → cutout run. If it happens, call the segmenter's raw results without the container rule for `cutout`, or union the pieces when `droppedContainer`.
7. **Blob orphans.** Re-cutting replaces candidates without deleting the old thumbs and masks, and abandoned change children keep their originals and previews. This is a post-hackathon cleanup, not a v0.8 item.
