# Founder-run scripts

Maintenance scripts for the live data, run from the repository root with the keys in `web/.env.local` (`vercel env pull` drops seven local-only keys; see `docs/rewind.md`). None of them is called by the apps.

- **Portraits:** `pnpm avatar <slug> <image file>` (480 px centre-square crop to public storage, then the creator's `avatar_url`; add `--dry-run` to check the crop without writing).
- **Replace a creator's live piece:** June Park's live sticker and tote are founder-provided illustrations (cleared for publication), not the seed's generated examples, which stay in `scripts/seed.ts`. They are put in place with `pnpm replace-art <slug> <file> <sticker|tote> [--box x0,y0,x1,y1] [--phrase "…"] [--title "…"] [--keep-old] [--dry-run]` from the repository root: the picture is upscaled ×2 when its short side is under 1800 px, cropped to `--box` (fractions of the picture), stored as the creator's photo and run through the app's own pipeline (SAM cut of the largest piece, product, listing agent, approval with the contrast warning accepted; a resolution failure still blocks), then the creator's earlier published products of that type are archived unless `--keep-old`. `--phrase` (repeatable) replaces SAM's default phrases. `--dry-run` only cuts and writes `./.replace-art/<slug>-<type>-{crop,cut}.png` (git-ignored), with no upload and no database call.
- **Move orders to a replaced product:** Orders placed on a product that was later replaced are re-pointed with `pnpm move-orders <from-product-id> <to-product-id> [--order <order-id>]... [--dry-run] [--allow-type-change]` from the repository root. It refuses unless both products belong to the same creator, the target is published and not deleted, the source is archived or published, and both are the same type (sticker to sticker, tote to tote; `--allow-type-change` lifts only that). It changes `orders.product_id` (and bumps the order's update time so the iOS inbox notices), in one guarded UPDATE on the orders it listed: amounts, shares, status, buyer, story tag, thank-you and messages stay with the order, and the iOS Orders inbox, the admin orders table and the story-tag page follow the new product because they read it through the join. Every non-deleted order of the source moves, or only the `--order` ids given. `--dry-run` reads only and lists the orders that would move, with buyer names as initials.
- **Story video recorded outside the app:** A story video recorded outside the app is added with `pnpm story-video <slug> <file.mp4> [--mention-disability] [--dry-run]` from the repository root (needs `ffprobe` and `ffmpeg` on the PATH). It does what the app's `POST /creators/me/story-video` does: it checks the file (an MP4-family container such as .mp4 or .mov, with H.264 video and AAC sound, at most 60 s and 100 MB), extracts the soundtrack to a 16 kHz mono 16-bit WAV in a temporary folder, stores the mp4 in the private store as `creators/<id>/story-video/<uuid>.mp4`, captions the WAV with Voice Transcribe, writes the creator's video, captions and transcript (a failed or silent captioning stores none, never the previous video's), and drafts a story from the transcript for the creator to Use, Edit or Skip in the app. `--mention-disability` sets that choice for the draft; without it the stored choice is kept. The previous video stays in storage. `--dry-run` checks the file and captions it (one model call) and prints the transcript, with no upload and no database call. Hand-uploaded videos should be faststart mp4s at a phone-friendly bitrate; June's current one was stored in the public store (plain URL) after the phone player would not start on a private link.
