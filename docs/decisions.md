- **Decision:** `API_BASE_URL` for the Debug configuration is the deployed site, same as Release; switch it to `http://localhost:3000` by hand when testing against a local server.
- **Why:** phone builds from Xcode are Debug, and the person testing on a phone should not need a dev server running. Supersedes the T051 note that Debug stays on localhost.

## 2026-10-29 · Studio-issued creator codes; hidden creators for testing (T070)
- **Decision:** no self-sign-up this week. The studio adds a creator on `/admin` and hands over a code (shown once, with a QR of `/create/code?c=<CODE>` and the iOS link `makerstory://code/<CODE>`). Creators can be marked hidden for testing: out of every public list and profile, but direct product links, story tags and sign-in still work. The sign-in link is as sensitive as a password; rotating the code revokes it (and the old code), while already-issued tokens run to their 30-day expiry.
- **Why:** real artists and testers had no way in (only the three seeded examples had codes); the product framing is "the code your studio gave you". A testing creator must not appear in the shop that judges and buyers see.
- **Alternatives:** public sign-up with email (rejected: no moderation of new accounts this week); a separate test database (rejected: iOS and Vercel share one database).
- **Details decided while building:** the `?c=` link pre-fills but never auto-submits; codes never appear in logs (driver errors are logged with query params cut, `lib/log-safe.ts`, which also covers the existing sign-in error logs); the table lists creators without codes; slugs come from the display name with `-2`, `-3` … on collision (soft-deleted slugs count, the unique index covers them); "Hide from shop" is a button per row rather than a switch so it works as a plain form post; rotating does not revoke existing sessions (there is no session store; a per-creator token version would be the follow-up).
## 2026-10-29 · iOS relies on system accessibility: no in-app TTS, no per-field mic, no settings sheet; the voice idea path stays (T081)
- **Decision:** the iOS app no longer speaks (no `AVSpeechSynthesizer`, no "Hear …" / "Read it to me" buttons), text fields have no mic buttons, approval is a tap (no "say yes"), the thank-you is typed, and the Accessibility settings sheet and Welcome helper-mode toggle are gone. Text the app used to speak is shown on screen and posted once as a VoiceOver announcement; the Voice result screen has a "WHAT THE IMAGE SHOWS" card (`spokenDescription`, else `altText`) and the picture's VoiceOver label is its alt text. Contrast follows Settings → Increase Contrast (`colorSchemeContrast == .increased` → `ThemeColors.highContrast`); Dynamic Type is allowed up to `accessibility5` with no lower clamp; `simpleMode` is still honoured (see below); `voiceFirst`, `speakDescriptions`, `highContrast`, `largeText`, `helperMode` are still decoded (the server stores them; the web reads `speakDescriptions`) but iOS does not read them. "Say it out loud" (record → Muse Voice Transcribe → shape prompt → Muse Image) and "Say what to change" on Voice result stay, because refine-by-voice is in the brief.
- **Why:** play-testing on TestFlight showed the app duplicating what iOS already does better and in the person's own settings: keyboard dictation, VoiceOver (in the voice and speed the person chose), Dynamic Type, Increase Contrast. Two speech sources talked over each other, and the in-app voice had caused a main-thread deadlock (see the 2026-10-29 `stopSpeaking` entry, now moot). Visible description text also serves deaf creators, which spoken-only output did not.
- **Sign out:** the settings sheet was the only way to sign out. The tab screens (My designs, Orders, Messages) now have a sign-out icon button in the header where the gear was; its confirmation shows who is signed in, the version and the server URL (the information the sheet used to show). ## 2026-10-29 · Photos of objects: two SAM phrases, mask finishing, soft alpha (T080)
- **Decision:** a photo or canvas upload is searched with `SAM_PHRASES = ["drawing", "handmade object"]` in parallel (two SAM calls), results are merged (IoU > 0.8 = same thing, higher score kept), anything covering > 95 % of the frame is dropped (paper, table), scores under 0.1 are dropped when anything scores higher, at most 6 candidates. ## 2026-11-03 · T153: when SAM's only masks fill the frame, the threshold fallback separates the pieces
- **Decision:** In `MetaSegmenter.findCandidates`, after dedupe, if every kept segment's mask covers more than `MAX_FRAME_COVERAGE` (0.95) of the frame, the threshold fallback runs on the same picture; if it gives at least 2 pieces that each cover at most 0.95, those are the answer (largest first, capped at `max`, `droppedContainer: true`), otherwise SAM's mask stays (`preferFallbackOverFill`, pure and unit-tested). **Why:** SAM answers "drawing" with one mask over the whole crop (the sheet), and since round 3 the frame path passes `maxCoverage: 1, dropContainers: false`, so that mask was kept as the only candidate and the fallback that used to separate the drawings never ran. **Trade-off:** one extra threshold pass on those photos, and a sheet the fallback cannot split into two or more pieces still comes back as the whole sheet (a tight frame around one piece is unchanged).
