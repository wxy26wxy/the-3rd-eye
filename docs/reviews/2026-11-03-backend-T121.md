## Summary
The preview is built in the same place as the print file. It is the same art over the white border, using the cut mask (`cut`) instead of the bleed mask (`bleed`). The outside is transparent, the image is trimmed, and it is downscaled to ≤ 1200 px without enlarging (`web/lib/image/sticker.ts:139-177`). `buildProductFiles` stores it as public `creators/<cid>/previews/<uuid>.png` (a public kind since T111) and sets `previewUrl`. `rebuildProductFiles` replaces it. Totes get `null` because `previewPng` is undefined (`web/lib/pipeline/products.ts:28-36, 72`).

Migration 0005 is a single `ADD COLUMN IF NOT EXISTS`. The schema matches it, and the helper prints `products.preview_url present`. `previewUrl` reaches `toProduct`, `ArtworkProduct` (both the select and the grouping in `listArtworksWithProducts`), and `ShopProduct`/`ProductDetail` through `toShopFields`.

The backfill:
- selects sticker products that are not deleted, whose artwork has `cleaned_url` and whose `preview_url` is null (`queries.ts:294-301`);
- renders with `composeSticker` only, with no mockup, no model call and no print rewrite;
- writes through a conditional `UPDATE … WHERE preview_url IS NULL`;
- supports `--dry-run`, prints counts, and exits 1 on failures.

### Minor
1. **The backfill also picks products whose artwork is soft-deleted.** `listStickersMissingPreview` (`web/lib/db/queries.ts:294-301`) filters `products.deletedAt` but not `artworks.deletedAt`. Those products are archived and not shown, so the only cost is a little extra work and a few unused public blobs. Fix (optional): add `isNull(artworks.deletedAt)` (or `ne(products.status, "archived")`).
2. **`ensurePrintFile` (`web/lib/pipeline/products.ts:80-91`) does not set the preview.** This is the repair path for products made before T050. It is harmless, since the backfill covers those rows, but the two paths disagree. Fix (optional): also store `files.previewPng` when `previewUrl` is null.
3. **The storage path differs from the brief.** The brief says `previews/<productId>.png`; the code writes `creators/<cid>/previews/<uuid>.png`. This is acceptable and actually better: a new name on every rebuild avoids stale CDN caching. It is documented in `docs/api.md` "Sticker preview (T121)" §3. No change needed.
4. **Mock `PUT /creators/me` answers `CREATOR` with `storyVideoUrl: null`** (`ios/scripts/mock_api.py`, the `ROUTES` entry). `GET` now returns the story video. A client that refreshes from the PUT answer would briefly see "No story video yet" against the mock only. Fix (trivial): merge `STORY` into the PUT answer as `creator_me` does.

## Concerns judged
1. **Deploy order (0005 before deploy).** Acceptable as a process gate, as with 0003 and 0004: every products query now selects `preview_url`. The user runs, in order, `pnpm migrate drizzle/0005_t121_product_preview.sql`, `backfill:previews --dry-run`, then `backfill:previews`, before this reaches `main` or a preview that points at the shared database. 0004 (T111) must already be applied. This is written down in `docs/handoffs/backend.md` and `docs/progress.md`.
2. **No bleed on the preview.** Acceptable, and correct for R1. The buyer and creator see the sticker as it will be cut (border to the die line). The bleed is a print-only margin that is trimmed away. The print file is unchanged. Tests check that the preview is smaller than the print, has the same aspect ratio, has a visible white band and has transparent corners.
3. **Old preview files are orphaned on rebuild.** Acceptable for v0.8. This matches mockups and the T111 Blob orphans (post-hackathon cleanup). The files are small (≤ 1200 px PNG).
4. **The mock video depends on `ios/App/Resources/Animations/sticker-loading.mp4`.** Acceptable. The file is present (114 KB), T120 keeps the name, and a missing file gives a clean 404 JSON instead of a crash. If T120 ever renames it, the fix is one constant (`STORY_MP4_PATH`).
