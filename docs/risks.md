# Risks

Open risks the team knows about, newest at the bottom. Format: date · risk · mitigation · owner · status.

- 2026-10-29 · **Rate limiting is per function instance only.** `proxy.ts` limits POSTs per IP in memory: `POST /api/v1/auth/code` and `/create/code/session` (and the `/create/bff` forward) 10 / minute, `/api/v1/public/*` and `/t/*` 30 / minute, model routes `/api/v1/(artworks|products|listings|prompts|transcribe|story)` and their BFF forwards 20 / minute; over the limit gets 429 with `Retry-After`. Each instance counts on its own, so it blocks naive brute force but is not a global limit, and `POST /uploads` is not limited yet. Login codes are random 10-character codes (about 50 bits) and tokens expire after 30 days. · mitigated in-app (per instance); Firewall rules when the plan allows · founder (Vercel dashboard) · mitigated
- 2026-10-29 · **Creator auth is dev-mode.** Shared login codes, HMAC bearer tokens with a 30-day expiry and no revocation list; rotating `CREATOR_SESSION_SECRET` signs everyone out. · Acceptable for the hackathon demo with fictional example creators; replace before real artists sign in. · backend · accepted for v0.1
- 2026-10-29 · **Client uploads are public until the server copies them.** Photos are re-encoded in the browser (EXIF and GPS removed) and the public upload is deleted after the private copy is stored; story and thank-you videos stay public by design (unguessable uuid pathnames). · Move client uploads to a private store when presigned private PUTs exist. · backend · open
- 2026-10-29 · **Muse Glimmer runs on the development Mac.** On Vercel the story stage falls back to Muse Spark 1.3 (`provider: "meta-fallback"`). The open-weight stage is only live when the demo runs locally or the Mac is reachable. · Documented in README; the response always says which provider wrote the draft. · team · accepted
- 2026-10-29 · **The sign-in link carries the creator code in its query string** (`/create/code?c=<CODE>`, T070). The code lands in Vercel request logs, browser history, and in any link-preview fetch when the link is pasted into a chat. · Treat the link like a password: hand it over by QR or in person, never post it in a group chat. If it leaks, use New code on `/admin`; the old code and link stop working at once (tokens already issued run to their 30-day expiry). Follow-up: a fragment link (`/create/code#c=<CODE>`, read in the browser) never reaches the server or its logs, but needs JavaScript. · web · accepted for the hackathon
  - 2026-10-30 update (T090): the copied link is now `/create/code#c=<CODE>`; the fragment never reaches the server, its logs or link-preview fetches, and the page strips the code from the address bar. The QR keeps `?c=<CODE>` (some scanners drop fragments), so a scanned QR still lands in request logs: show it in person only. · web · mitigated (QR form accepted)

- 2026-10-29 · **Two SAM calls per photo** (T080: `"drawing"` and `"handmade object"`) ≈ 2× the segmentation cost and a little more latency (they run in parallel). A cleanup with points or a box is one more call; combining candidates is free. Cleanup on an artwork with products also rebuilds each product's mockup (one Muse Image compose each, ≈ 16 s). · Watch `ai_calls` cost per artwork; drop to one phrase for canvas uploads if cost matters. · backend · open
- 2026-10-29 · **When SAM finds nothing in a photo, the threshold fallback is ink-on-paper only** and can return a dark table as a "drawing" (seen live on a knitted bear when only `"drawing"`/`"object"` were used). With `"handmade object"` the bear is found; other scenes may still hit the fallback. · The creator can now fix it with a box or points (`cleanup`). · backend · open
- 2026-10-29 · **Replaced print files and mockups are not deleted from Blob** after a cleanup rebuild (orphans, private and public). · Harmless for the demo; add a cleanup job later. · backend · open
- 2026-10-29 · **Re-cut memory on large photos** (T080 review minor 5): a small object in a 12 MP photo upscales the whole frame ×2 before cutting (≈ 400 MB RSS measured on flat colour). · Crop to the selection plus a margin before upscaling (deferred). · backend · open
- 2026-10-29 · **A paper/table region covering 30–40 % of the frame can still become a candidate** when "drawing" finds few pieces (seen at 37 % with score 0.41; it lost only on score). · The creator can pick another candidate or adjust; lower `MAX_CONTAINER_COVERAGE` if it shows up in play-tests. · backend · open
- 2026-10-30 · **Buyer-note moderation outage** (T090 closes the v0.1 minor): a failing moderation provider now answers `503 moderation_unavailable` on the story-tag form, `/public/reply` and checkout (with "remove the note and try again"), never 500; notes still fail closed (nothing is stored unchecked). · — · backend · closed
- 2026-10-30 · **Public-original delete was unscoped** (T090 closes the v0.1 minor): the delete after the private copy now only touches `photo` / `photos` / `canvas` uploads, never thumbs, mockups, videos or other own files passed as `imageUrl`. · — · backend · closed
- 2026-11-03 · **Blob operations on the Hobby plan (round 4).** The plan allows 2,000 advanced operations (writes) and 10,000 simple operations (reads) a month and pauses, rather than bills, at the limit (≈ 100–150 creator runs at v0.9). Round 4 changes the count: a photo costs **the same writes** as before (one client PUT of a smaller file, the server's private original, the public upload deleted), but **each re-frame now costs a new upload and original** (a new row), and the product is made before Change it and **rebuilt once per change** (one product build per change, an **estimate** of ≈ 5 advanced operations from the round 4 plan, not measured: the print file, the die-cut SVG, the sticker preview and the mockup are each a new write), and each "Fix the cutout" rebuilds the row's products again. Abandoned change products and frames re-cut as new rows stay as drafts (files kept). Long-lived public caching (one year, write-once pathnames) and the iOS image cache cut repeat reads. · Watch the Blob usage page during the demo week; rehearse with the Test Artist only; replaced files are still not deleted (see 2026-10-29). · founder · open
